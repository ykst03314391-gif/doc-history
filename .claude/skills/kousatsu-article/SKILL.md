# 考察記事の作り方（問いから公開できる形まで）

このサイトの主役は考察記事で、人物・合戦・城のページはそれを支える脚注（README の「コンセプト」）。だから作業は**「この問いを記事にしたい」から始まり、DB のページはその途中で、記事に要る分だけ作る**。

ひな型は「秀長は「補佐役」で満足していたのか」。①論文版は `drafts/hidenaga-independence.md`、②Web記事は `data/articles/hidenaga-independence.md`。迷ったら、この2つの同じ箇所を開いて、同じ形・同じ調子で書く。

決まりの置き場所：記事のメタと本文の記法は `docs/schema-article.md`、2層の書き分けは `drafts/README.md`、挿絵・図解・漫画の作り方は CLAUDE.md、公開の出し方は `docs/公開の方針.md`、出典の当たり先は `docs/sources.md`。ここに書くのは、それらをつなぐ**順序と判断**。

## 全体の流れと、管理人に見せる区切り

| 段階 | すること | 区切り |
|---|---|---|
| 1. 問いと構成案 | 問い・論点・結論の向き・使う原典・要るページを決める | **管理人の OK を待つ** |
| 2. 調べもの | 原典を引き、足りなければ取得して保存する | — |
| 3. ①論文版 | `drafts/<id>.md` に論証を書く | **管理人に見せる**（結論は管理人が確定） |
| 4. ②Web記事 | `data/articles/<id>.md` と `index.json` | — |
| 5. DB のページ | 記事に要る人物・合戦・城のページ | 4 と合わせて**管理人に見せる・コミット** |
| 6. 挿絵・図解・漫画 | 仮の SVG を入れる | **管理人が表示を確かめる・コミット** |
| 7. 仕上げ | ネタ帳の整理・確認・報告 | コミット |

- 区切りでは、作ったものを短くまとめて見せ、`コミットしますか` と聞いて止まる（CLAUDE.md の「コミット」。プッシュは指示があるときだけ）。
- 1 の OK が出る前に 2 以降へ進まない。3 で管理人が結論を書き換えたら、それに合わせて 4 以降を書く。

## 1. 問いと構成案

- **問いを決める**：管理人の言葉（例「なぜ信長包囲網は成功しなかった？」）をそのまま出発点にする。`drafts/_ideas.md`・`docs/article-ideas.md` に同じか近いネタがあれば、そこに書いてある「問い・主張の芽・出典の当て・動線」を引き継ぐ。なければ、書き始めるときに `drafts/_ideas.md` の該当する章に足す。
- **問いの形**：通説をなぞらず「本当にそうか？」「なぜそうなったのか」と問う（README の「一貫する態度」）。答えの決まってしまう問い（秀長の「実弟か」は異父でも実弟なので決まる）は、論点がずれないよう言い直す（「父が同じか」）。
- **構成案として管理人に出すもの**（短く）
  1. id（英小文字とハイフン。例 `nobunaga-hoimou`）・題・特集（`series`：economics／myth-busting／travel／なし）・`group`
  2. 問いと、それを分けた**論点2〜4つ**（秀長：①兄との仲 ②独立する気 ③そもそも補佐役か）
  3. 結論の向き（いまの見込み。確定は 3 のあと）
  4. 使う原典（`reference/` にあるもの・取得が要るもの）と研究
  5. 要る DB のページ：主役にする人物・脇役で作る人物・合戦・城（下の「5」の考え方で）
- 管理人が「任せる」と言った項目だけ、Claude の案で進める。

## 2. 調べもの

調べ方は person-page スキルの「調べ方」と同じ（`reference/` を grep、手元にない原典は取得して `reference/` に来歴付きで保存、Web 検索で見つけた事柄は原典の中身まで当たる、量が多ければサブエージェント）。記事で特に気をつけること：

- 論点ごとに、**同時代の史料（一次）で言えること／後世の軍記・逸話（二次）が言うこと／研究者の読み**を分けて集める。この3つの書き分けが記事の骨になる。
- 通説の**出どころ**（いつ、誰が、何をもとに言い出したか）を必ずたどる。小説・ドラマは事実の典拠にはしないが、像の出どころとしては扱う。
- 研究書・論文は書誌（著者・年・頁）を確かめる。中身を見ていなければ「本は未見」と書く。
- **出典が分からない事柄は「出典未確認」で統一する**（表の出典の列でも、本文・論文版の括弧書きでも）。「一般の年表による」「一般の解説による」「通説による」のような、どの本か分からない書き方を出典の代わりにしない。原典で確かめられたら史料名に差し替える。

## 3. ①論文版（`drafts/<id>.md`）

ひな形 `drafts/_template.md` を写して書く。大学院の論文のつもりで、**厳密・出典完備・論証つき**（`drafts/README.md`）。

- 冒頭に、対応する②の場所と状態（「論証中（結論は管理人の見立ての叩き台。管理人が手を入れて確定する）」）。
- **問い・主張** → **前提・通説の整理** → **論証**（論点ごとに `###`、その下に `####` で根拠を番号付き：1-1、1-2…）→ **反証の検討** → **結論** → **参考文献・出典** → **要確認** → **Web記事化メモ** の順。
- 史料は原文を `{{…}}` で引き、出典（史料名・巻や条・年月日、`reference/` のファイル）を添える。確かさは語尾で書き分ける（言い切る／〜とされる／〜とみる（著者 年）／〜とみられる）。
- **結論は叩き台**として Claude が書き、管理人が確定する。管理人の見立て（人物ページの `lens.view` に当たるもの）を Claude の言葉で決めてしまわない。
- 確かめきれない事柄は本文で断定せず、「要確認」の節に、何が分かっていないか・何に頼っているか・当たるべき資料を書く。
- 「Web記事化メモ」に、噛み砕きの方針（どこを削り、どこを残すか）・冒頭画像・動線（関連人物・合戦・城・記事・関連書籍）を書く。

## 4. ②Web記事（`data/articles/<id>.md` と `index.json`）

①を一般向けに噛み砕く。①にないことは書かない（新しい事実を足すなら先に①へ）。

### 画面の構成（上から順に）

| 位置 | 置くもの | 決まり |
|---|---|---|
| 1. 最初 | **サムネイル（冒頭画像）** | `index.json` の `image`。**必ず入れる**。題の直下に大きく出て、一覧のカードのサムネイルにもなる |
| 2. 冒頭 | 題・導入・問い・**答え** | 問いのすぐ下に「先に答えを言うと」の囲みで答えを明記する。読者が冒頭だけで結論を持ち帰れるようにする |
| 3. 本文 | 論点（章 `##`）と小見出し（トピック `###`） | **挿絵は小見出しごとに1枚**。図解は要るときだけ任意に足す |
| 4. 各論点の終わり | 論点の結論の囲み | 論点ごとに1つ |
| 5. まとめ | 問いへの答え・筆者の見立て | まとめにも挿絵を1枚 |
| 6. 記事の終わり | **漫画** | まとめの後、参考文献の前に1本 |
| 7. 本文の後 | 関連人物 | `relatedPeople` から自動で出る（人物ページへの札） |
| 8. その後 | 参考文献・出典と断り書き | 本文末の `## 参考文献・出典` 以下が、本文の枠の外に出る |
| 9. その後 | **関連書籍（アフィリエイト）** | `index.json` の `references` から自動で出る。開示文も自動 |
| 10. 最後 | **誤り・出典のご指摘** | 窓口は `article.js` が全記事に自動で出す。記事ごとに書かない |

- **サムネイルの選び方**：問いの中心になる人物の肖像（人物ページの `portrait` の表記を写し、`caption` に「※参考イメージ」）、記事の舞台の城・合戦の写真（城・合戦の `photo` の表記を写す）、どちらもなければ記事の主題を描いた SVG（挿絵と同じ画風。表記は「イラスト：戦国クロニクル（AIで作成）」）。本文に同じ画像を重ねない。
- **答えの書き方**：2〜3文。「分からない」ことが答えの一部なら、それも書く（秀長：「満足していたかどうかは、本人の言葉が残っていないので分からない。ただ…」）。問いを繰り返すだけ・「以下で見ていく」で済ませない。
- **挿絵**：章（論点）の中の小見出し（トピック）ごとに1枚。見出しのない「まとめ」も1つと数える。図解・漫画は数えない。
- **図解**：関係図・年表・地図のように、文章だけでは追いにくい説明を助けるときに任意で入れる。図解のある小見出しにも挿絵は1枚入れる。
- **漫画**：記事の最後に1本だけ。章ごとには置かない。

### アフィリエイト（関連書籍）
- 置くのは**記事末の「関連書籍」だけ**（`index.json` の `references`）。本文に広告・購入ボタン・アフィリエイトのリンクを挟まない（README の「掲載ルール」）。
- **載せる本**：記事で引いた・論証に使った本、記事の問いをさらに深められる本（新しい研究書・評伝が中心）。記事で扱った「像の出どころ」の小説も、そう断って載せてよい。文脈に関係しない本は載せない。目安は2〜4冊。
- **書き方**：`{ "title", "author", "affiliateUrl", "note" }`。`note` は「何が書いてある本か」と、この記事とのつながりを1文（秀長：天野忠幸の本に「副題そのものがこの記事の問い」）。
- **リンク**：Amazon の商品ページ（`https://www.amazon.co.jp/dp/<ASIN>`。提携のタグは管理人が付ける）。ASIN が分からなければ `XXXXXXXXXX?tag=YOUR_ASSOCIATE_TAG-22` の仮の形にし、`note` に「※リンクは仮。登録後に実商品URL＋タグへ差し替え」と書く。ISBN・ASIN は推測で書かない。
- 開示文（「Amazonのアソシエイトとして…」）と `rel="sponsored nofollow"` は `article.js` が付けるので、本文にもメタにも書かない。
- 本を勧める文に、記事の考察を曲げない（売るために評価を甘くしない）。

### 誤り・出典のご指摘
- 窓口は全記事の末尾に自動で出る（`docs/公開の方針.md` の「読者の声の受け方」）。外部のフォームの URL が決まるまでは押せない見本で、URL は `js/article.js` の `FEEDBACK_URL` に1か所だけ書く。記事の本文やメタには書かない。
- 記事の側で受け止められるようにしておく：確かめきれていない点は、本文末の断り書き（`※ 本記事は管理人の解釈です。…`）に短く並べる。読者の指摘が、どこを確かめればよいかの手がかりになる。
- 届いた指摘で直すときは、①論文版を先に直し、②・DB のページへ同じ直しを広げる。

### 本文の組み立て（ひな型の順）
1. `# 題`
2. **導入**：通説の像（「〇〇といえば〜だ」）→ それだと不思議な点 → 問い（1文で独立させる）。登場人物は初出で人物ページへリンク（`[秀吉](person.html?id=toyotomi-hideyoshi)`、合戦は `battle.html?id=…`、城は `castle.html?id=…`）。
3. **先に答え**：`<div class="lead-answer"><span class="lead-answer-label">先に答えを言うと</span><p>…</p></div>`（2〜3文）。
4. **論点の予告**：「以下、この問いを三つに分けて確かめていく。」と、①②③を `<br>` で並べる。
5. **論点ごとに `## 論点①：…`**、その中を `### 小見出し` で2〜4つに分ける。節の終わりに `<p class="sec-conclusion"><span class="sec-conclusion-label">論点①の結論</span>…</p>`。
6. `## まとめ`：問いへの答え。筆者の見立ては「私には〜と思える」と一人称で出す（中立を装わない）。
7. **記事末の漫画**（6 で入れる）。
8. `---` のあと `## 参考文献・出典`：史料（区分：一次資料／二次資料を添える）・研究・小説（像の出どころとして）。
9. 最後に `※ 本記事は管理人の解釈です。…` の断り書きと、確かめきれていない点の短い一覧。

### リンク・文字の太さ・色・下線

見た目は `css/style.css`（`.article-body`）が記法から付ける。**本文に色・下線・文字の大きさを HTML や style で書かない**。使ってよい記法は下の表と、`docs/schema-article.md` の囲み・画像の記法だけ。

| 見え方 | 記法 | 使いどころ・決まり |
|---|---|---|
| 朱の文字に、薄い朱の点線の下線 | `[語](person.html?id=…)`・`battle.html?id=…`・`castle.html?id=…`・`article.html?id=…` | サイト内のページへのリンク。下の「リンクの張り方」 |
| 太字（700） | `**…**` | **筆者の主張・その節の答え**。小見出し1つにつき1か所まで |
| 金の蛍光線（下線ではない） | `==…==` | **論拠の要になる事実**。小見出し1つにつき1か所まで。リンクの点線と紛れないよう、強調に下線は使わない |
| 藍の「…」 | `{{…}}` | 史料の原文の引用。太字・蛍光線を重ねない |
| 朱の上罫の囲み・朱の札「先に答えを言うと」 | `lead-answer` の div | 冒頭の答え。1記事に1つ |
| 朱の左罫の囲み・本文より太字 | `sec-conclusion` の p | 論点の結論。論点ごとに1つ。囲みの中にさらに太字を足さない |
| 薄い朱の左罫・薄茶の地・灰色の文字 | `> …` | 一文以上の史料の原文を独立させて引くとき（`> {{…}}`。荒木村重の記事）。補足の囲みには使わない |
| 罫線の表・見出しの行は薄茶の地・出典の列は小さく灰色 | `| 年月日 | できごと | 出典 |` の表 | **年表（出来事の流れ）は必ずこの3列の表で書く**。箇条書きで並べない。年月日は「天正19年（1591）正月22日」、2行目からは「同年8月」と書いてよい。出典は史料名（『多聞院日記』など）、原典で確かめられなかったものは「出典未確認」。リンクはできごとの列に、記事の初出なら張ってよい |
| 章：1.35rem・頭に朱の「◆ 」・下に罫線／小見出し：1.2rem・朱の左罫 | `##`・`###` | 見出しの記号（◆・①など）は自分で書かない。論点の番号は「論点①：」の形で見出しの文に入れる |
| 藍の札「図」・罫線の箱／朱の札「漫画」 | `![[zu:…]]`・`![[manga:…]]` | 札と表記は自動で出る |

- 色は CLAUDE.md の「文字と色」の色だけを使う。新しい色を足さない。
- 太字・蛍光線は付けすぎると効かなくなる。1段落に両方を入れない。
- `この**「…」…**` のように文字のすぐ後に `**「` と続けると太字にならない（Markdown の決まり）。太字の始まりを前の語に寄せる（`**この「…」…**`）。

### リンクの張り方
- **張る相手**：ページのある人物・合戦・城と、公開済みの記事。ページがなければ張らない（記事に要るなら 5 で概要ページを作ってから張る）。作らないと判断済みの人物（CLAUDE.md）には張らない。
- **張る場所**：その語の**記事の中での初出1か所**。同じ人物を何度もリンクにしない。見出し・「先に答えを言うと」・論点の結論の囲み・漫画の説明の中には張らない（初出が見出しにあるなら、すぐ後の本文の初出に張る）。
- **語の形**：本文に出てくる形のまま（「秀吉」「信長」）。初出で「木下藤吉郎（秀吉）」のように書くなら、呼び名の部分をリンクにする。
- **ほかの記事へ**：関連する公開済みの記事は `[題](article.html?id=…)` で本文から張ってよい。まだ公開していない記事（`draft`）へのリンクは張らない（`docs/公開の方針.md` のリンク切れ）。
- **外のサイト**：本文には張らない。出典は参考文献に書名で、関連書籍は `references` に書く。

### 書きぶり
- **長さ：本文は4,000〜5,000字を目安にし、6,000字を上限とする**。数えるのは題から「まとめ」の終わりまでの本文の字で、見出し・記法（リンクの URL・`![[…]]`・囲みのタグ・`**`・`==`・`{{ }}`）・空白と、`---` の後の参考文献・断り書きは数えない。超えるときは、①論文版に残して②から削る（論点の数・小見出しの数・年表を見直す）。①論文版には上限を設けない。
- 常体で短く平易に。史料の原文は要所だけ `{{…}}` で引き、すぐ後に現代語で言い直す。
- 強調は `docs/schema-article.md` の「強調と囲みの記法」どおり。**小見出し1つにつき太字1か所（筆者の主張）・蛍光線 `==…==` 1か所（論拠の要の事実）まで**。
- 年は「天正13年（1585）」。
- 本文に広告を挟まない。関連書籍は `index.json` の `references` だけ。

### `index.json` のメタ
- `id`・`title`・`series`・`group`・`category`（考察）・`summary`（問いと、何から考えるかを2文。一覧のカードに出る）・`date`・`author`（管理人）・`image`（冒頭画像。人物の肖像なら `portrait` の表記を写し、`caption` に「※参考イメージ」）・`relatedPeople`・`relatedBattles`・`tags`・`references`。
- `relatedPeople` に入れた人物は、人物ページの「関連する考察・記事」と、人物一覧の「登場する記事」に出る。記事の中で扱う人物を入れる（名前が1度出るだけの人は入れない）。
- 関連書籍の `affiliateUrl` が仮なら、`note` に「※リンクは仮」と書く。
- 公開前の扱いは `docs/公開の方針.md`（`date` は公開した日にする、まだ出していない記事へのリンクを公開済みのページに入れない）。

## 5. 記事に要る DB のページ

記事を書くと、人物・合戦・城のページが要るかが決まる。**記事が必要とする範囲だけ**を作り、網羅に広げない。

- **人物**：person-page スキルで作る。主役か脇役かは、記事から決まる。
  - その記事の**問いの中心になる人物**（記事がその人を捉え直す。例：包囲網の記事なら足利義昭）→ 主役（詳細ページ）。
  - 記事の論証に出てきて、読者が「誰だっけ？」となる人物 → 脇役（概要ページ）。
  - 名前が出るだけの人物 → ページを作らず、リンクもしない。
  - 中心人物がすでに主役なら、記事の論点に関わる欄を確かめ直し、記事と食い違いがないかを見る（person-page の「ほかのページとそろえる」）。
  - 中心人物が誰か分かれる記事（包囲網のように複数の大名が並ぶもの）は、1 の構成案で管理人に聞く。
- **合戦・城**：記事の論点に出てくるものを概要で作る（スキーマは `docs/schema-battle.md`・`docs/schema-castle.md`）。地図のピンに使うので、`index.json` に `lat`/`lng` を入れる。
- 作ったら、記事の本文からリンクを張り、`relatedPeople`・`relatedBattles` に入れ、人物ページの `questions` の `article_id` で記事につなぐ。帰りのリンクは person-page の手順で張る。

## 6. 挿絵・図解・漫画

作り方と記法は CLAUDE.md の「記事の挿絵」「記事末の漫画」「図解」に従う。要点：

- **挿絵**：小見出し（`###`、見出しのない「まとめ」も含む）ごとに1枚。節の中で絵の内容に当たる段落の後に置く（迷ったら節の終わり、結論の囲みより前）。Claude が仮の SVG を `assets/img/illust/<名前>.svg` に作り、`![[illust:<名前>|説明]]`。場面の絵は「（想像図）」、たとえの絵は「（イメージ）」。史料で確かめられない顔・服装・家紋は描き込まない。
- **図解**：本文の説明に要るときだけ。`assets/img/zu/<名前>.svg`（地色を塗らない）、`![[zu:<名前>|題|説明]]`。挿絵の枚数には数えない。
- **漫画**：「まとめ」の後、参考文献の前に1本（1・2・4コマ）。`assets/img/manga/<名前>.svg`、`![[manga:<名前>|題|説明（創作）]]`。セリフは SVG の文字で重ね、記事で否定した通説を広め直さない。
- 構図は、管理人が決めるか Claude が案を出す。仮の SVG を入れたら管理人に表示を確かめてもらい、本番の絵（Gemini か手描き）への差し替えは管理人の OK のあと。

## 7. 仕上げ

### ネタ帳の整理
- 記事にしたネタを `drafts/_ideas.md`・`docs/article-ideas.md` から消す。目次の件数と、ほかのネタの「動線」でそのネタを指していた箇所を、記事の id を指す書き方に直す。
- 書く途中で出てきた新しい問いは、`drafts/_ideas.md` の該当する章に足す。

### ブラウザで確かめる
確認用のサーバー（`python -m http.server 8765`。立っていなければ立て、「閉じて」と言われるまで止めない）で、Brave で開いて見る。
- 記事（`article.html?id=<id>`）：冒頭画像と表記・「先に答えを言うと」の囲み・論点ごとの結論の囲み・太字と蛍光線・原文の藍・挿絵/図解/漫画の札と説明と表記・人物/合戦/城へのリンク（初出1か所だけか）・関連人物・参考文献・関連書籍（本の札・Amazon のボタン・開示文）・誤り・出典のご指摘の窓口。
- 記事一覧（`articles.html`）：特集とグループの中に出るか、カードの要約と画像。
- 関わる人物ページ：「関連する考察・記事」に出るか、`questions` から記事へつながるか、新しく作ったページの表示（person-page の仕上げのチェック）。
