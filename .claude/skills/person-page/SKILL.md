# 人物ページの作り方（秀長ページをひな型に）

人物ページ（`data/people/<id>.json`）を作る・書き足すときの手順と書き方。ひな型は豊臣秀長のページ `data/people/toyotomi-hidenaga.json`。迷ったら秀長の該当する欄を開いて、同じ形・同じ調子で書く。フィールドの型は `docs/schema-person.md`、出典の当たり先は `docs/sources.md` にある。ここに書くのは、スキーマに載らない**判断と書きぶり**。

## まず、どちらのページを作るのか決める

人物は主役・脇役・名前だけの3段階で扱う（CLAUDE.md の「進め方」）。詳細ページを書くのは主役だけ。

| | 概要ページ（脇役） | 詳細ページ（主役。秀長型） |
|---|---|---|
| いつ | 主役ページや記事からリンクを張るために、その人のページが必要になったとき | 管理人がその人物について考察を書くと決めたとき（考察記事がある人物） |
| 書く欄 | `id`・`name`・`kana`・`summary`・生没年（`birth`/`death`）・`tags`。分かれば `aliases`・`category`・`portrait` | 下の「欄ごとの書き方」のすべて |
| 書かない欄 | 年表・家系・逸話・出典などの詳細 | （`history` はどちらでも書かない） |

### 記事から呼ばれたとき（ふつうはこちら）

人物ページは、ふつう考察記事を書く途中で要るようになる（kousatsu-article スキルの「5. 記事に要る DB のページ」）。このとき主役か脇役かは**記事から決まる**ので、改めて聞かない。

- その記事の問いの中心になる人物（記事がその人を捉え直す）→ 主役。下の「主役で作るとき」の付随作業もする。
- 記事の論証に出てきて、読者が「誰だっけ？」となる人物 → 脇役。
- 名前が出るだけの人物 → 作らない。
- 主役のページは、**その記事で使う欄（論点に関わる年表・家系・人物評価・疑問など）から書き始めてよい**。記事の裏取りで当たった原典をそのまま使える。残りの欄も同じ作業の中で、上限と書き方に沿って埋める。記事で使わない欄だけを後回しにするときは、報告でそう伝える。
- 記事と人物ページで同じ事柄を書くときは、①論文版で確かめた書き方にそろえる。

### 「〇〇のページを作成」と単独で指示されたら

主役か脇役かは**管理人の指示に従う**。

- 「主役で」とあれば主役（詳細ページ）、「脇役で」とあれば脇役（概要ページ）で作る。
- **どちらとも書いていなければ、作り始める前に管理人に確かめる**（AskUserQuestion で「主役（詳細）／脇役（概要）」を聞く）。いまの段階（`index.json` の `role`。無指定は脇役、`"frozen"` は凍結中）を添えて聞く。
- **主役で作るとき**は、ページと一緒に次もそろえる（記事から呼ばれたときも同じ）。
  1. 個別ファイルと `index.json` の `role` を `"main"` にする。
  2. CLAUDE.md の「進め方」の主役の一覧（「いまは豊臣秀長・…」）に名前を足す。凍結中の人物なら、凍結の人数（「46人」など）も1人減らす。
- **凍結中（`"frozen"`）の人物を主役に上げるとき**は、すでにある記述をすべて仮置きとみなし、秀長と同じ手順で出典を1つずつ当たり直す。確かめられた記述だけを残し、確かめきれない記述は要確認へ移す。既存の文を手直しして済ませない。
- 脇役で作るときは、概要ページの欄（上の表）だけを書く。詳細の欄は、主役にすると指示されるまで書かない。

### そのほかの決まり

- **ページを作るかどうかを先に決める。** 名前が出てくるだけでは作らない。主役ページや記事から参照する必要があるかで判断する。作らない人はリンクにせず `name` だけで書く。判断済みの人（CLAUDE.md の10人）は作らない。新たに「作らない」と決めたら CLAUDE.md の一覧に足す。
- **主役でない人を詳細に書き広げない。** 概要ページの人物を詳細にするのは、管理人がその人を主役にすると指示してから。すでに詳細まで書いてある主役以外の人物（凍結中。`role: "frozen"`）にも、指示なく書き足さない。
- 詳細ページを作っても、そこから出てくる人物・合戦・城を「新しく作る候補」として広げない。リンクに要る脇役だけを概要で作る。
- 武将でない人（家族・僧・商人など）は `category: "other"`（個別ファイルと `index.json` の両方）。
- 詳細ページで新しい人物にリンクを張るとき、その人の概要ページを同時に作る（`person_id` が空振りしないように）。

## ページの章立て

人物ページは、冒頭の「概要」のあとに5つの章を並べる（並びと章の見出しは `js/person.js` の `GROUPS`、表示の決まりは `docs/schema-person.md` の「ページの並び」）。**考察が主役でデータは脚注**なので、問いを立てる「捉え直す」を先頭に、出典と調査メモを最後に置く。中身のない欄・章は表示されないので、空の欄を埋めるために書かない。

各章は「読者のどんな問いに答えるか」で中身を決める。章ごとに、答える問い・置く欄・書くこと・書かないことは次のとおり。欄の細かい書きぶりは下の「欄ごとの書き方」。

### 概要（ヘッダー。見出しなし）
- **答える問い**：この人は誰で、ひとことで言うと何をした人か。
- **置く欄**：名前・読み（`name`・`kana`）、生没年（`birth`・`death`）、一言紹介（`summary`）、肖像画（`portrait`）、ぱぱねこ版の絵（`papaneko`。主役だけ）、基本情報（改名 `aliases`・家紋 `kamon`・出生地 `birthplace`・分類 `tags`）。仮置きの注記（凍結中なら「詳しく書き足していません」の断り書き）はここに自動で出る。
- **並び**：冒頭の枠は、目次のレールの左端まで広げてある（幅900px以上。枠の上の「← 一覧へ戻る」と仮置き注記・凍結の断り書きも同じ左端にそろう）。枠の中は、左から本文（名前〜基本情報）、肖像画、ぱぱねこ版の絵の順に並ぶ。スマホでは2枚の絵が横に並んで本文の上に来る。どれも `person.js`・`css/style.css` がするので、データには位置を書かない。
- **書くこと**：`summary` は「誰の何か」→「代表的な事績2〜3」→「どう終わったか」の2〜3文。読み終えた人が、下の章のどこを読めばいいか見当がつく程度にとどめる。
- **書かないこと**：評価や結論（「名補佐役だった」など）。評価は「捉え直す」で問いとして扱う。肖像画・ぱぱねこ版の絵・家紋の絵の権利表記（所蔵・作者・ライセンス・出典）もここには出さない。コードがページ末尾の「画像の出典」にまとめる。
- **脇役（概要ページ）はこの章だけで終わる**。下の5つの章は主役（詳細ページ）だけが持つ。

### 1. 捉え直す ― 本当にそうか？
- **答える問い**：今よく語られるこの人物像は、本当にそうか。どこから来た像か。
- **位置**：ふだんは5つの章の先頭。その人物の連載（記事の `index.json` の `rensai`）が出ているときは、考察を連載に任せるので、この章は「誰だっけ？」の後ろ・「もっと知りたい！」の前へ下がる（`person.js` が並べ替える）。
- **置く欄**（この順）：この人物への問い（`lens`）→ 人物評価（`reputation`）→ 諸説・疑問（`questions` のうち `place` が `lens` か無指定のもの）→ 関連する考察・記事（自動）。
- **書くこと**
  - `lens`：人物像を問い直す大きな問いを1つ（秀長：「補佐役」という秀長像は、同時代の史料から見てどこまで当たっているのか。兄との関係・領主として・政権の中で、の三つの面から確かめる）。`place: "lens"` の論点は、問いのどの面を確かめるのかを `aspect` に短く書く（札が「論点1：兄との関係」と出る）。論点の記事がそろったら、論点を束ねた答えを `answer` に書く（最後の論点の下の「まとめ」に出る。史料から言える読みだけで、Claude はたたき台を書き、管理人が確定する）。見立て（`view`、史料の外へ出る私見）は管理人だけが書く。
  - `reputation`：同時代の日記・書状がどう書いたか（存命時）と、江戸の軍記から近代の小説・現代の研究までの描かれ方の移り変わり（死去後）。出典ごとに1項目。
  - `questions`：大きな問いを支える小さな問い。何が分かれているか・何を確かめるかだけを書き、結論は記事に回す。記事があれば `article_id`。
  - 関連する考察・記事：手で書かない。記事の `relatedPeople` にこの人物の id を入れると出る。ページの中ですでにリンクした記事（`article_id` を付けた家系・疑問の項目や、記事の `relatedBattles` と合う年表の合戦に出したもの）と、下書きの記事は出ない。
- **書かないこと**：問いへの答え（記事の役目）。記事の要約の貼り付け。
- **この時点で考察記事は作らない**。人物ページで立てるのは問い（`lens`・`questions`）までで、その先の記事（`data/articles/` の本文・`index.json` への登録・`drafts/` の論文版）は書かない。記事を書くかどうか、いつ書くかは管理人が決め、決まったら別の作業として起こす。問いの `article_id` は、記事がすでにあるか、管理人が書くと決めて下書きを登録したときだけ付ける。

### 2. どんな人だっけ？ ― 事績と生涯
- **答える問い**：この人は、いつ、どこで、何をしたのか。
- **置く欄**（この順）：成し遂げたこと（`achievements`）→ 年表（`timeline`）→ 領地の変遷（`territories`）→ 逸話・エピソード（`episodes`）。
- **書くこと**
  - `achievements`：生涯の要点3つ前後。年表を縮めたもので、新しい事実は書かない。
  - `timeline`：史料で日付を言える出来事。史料に出てこない期間は「記録の空白」として1項目置く。合戦・城のページへは `battle_id`・`castle_id`（地図にピンが立つ）。
  - `territories`：いつ、どこを、どれだけ持ち、いつ手放したか。国の一部なら郡で塗る。
  - `episodes`：人柄の分かる話を、伝える史料の性格（顕彰の文章か、後世の逸話集か）とセットで。
- **書かないこと**：伝承で埋めた生い立ち。確かめられない参陣を言い切ること（「〜とされる」と要確認にする）。

### 3. 誰だっけ？ ― 家系・主従・呼び名
- **答える問い**：この人は誰の子・誰の家族で、誰に仕え、誰を従え、何と呼ばれたのか。
- **置く欄**（この順）：家系・親族（`family`）→ 仕えた人（`lords`）→ 家臣団（`retainers`）→ 与力（`yoriki`・`yorikiNote`）→ 官位（`ranks`）→ 呼び名の変遷（`nameHistory`）。素性の謎は、関わる欄の末尾に `questions`（`place: "family"`・`"nameHistory"` など）で置く。
- **書くこと**
  - `family`：生前に成立した関係だけ。続柄は具体的に。ページのない家族も名前で載せる。
  - `lords`・`retainers`・`yoriki`：家臣だったと史料で示せる人を家臣団に、主君から付けられた大名は与力に分ける。
  - `ranks`：任官の日付と、日記と名簿で食い違うときの両方の日付。
  - `nameHistory`：その時期に史料が実際どう呼んでいるかを、原文 `{{…}}` で時系列に。
- **書かないこと**：死後の縁組（相手側の注記で伝える）。異説のある続柄の結論（両説を短く示し、記事へ）。

### 4. もっと知りたい！ ― 読む本・行く現地
- **答える問い**：この人のことをもっと知るには、何を読み、どこへ行けばいいか。
- **置く欄**（この順）：参考書籍（`references`）→ ゆかりの地・史跡（`spots`。墓所 `graves` もこの欄の中に出る）。
- **書くこと**
  - `references`：新しい研究書・評伝を中心に、何が書いてある本か。アフィリエイトのリンクはここだけ。
  - `spots`・`graves`：城跡・寺社・博物館など、行ける場所。地図に出すため、城ページか座標を付ける。墓は現存かどうかと、墓所・供養塔などの区別。
- **書かないこと**：小説や一般向けの記事を、事実の典拠として紹介すること（小説は人物評価の「描かれ方」の資料として扱う）。

### 5. 出典と確認状況
- **答える問い**：このページの記述は何に基づき、どこまで確かめてあるか。
- **置く欄**（この順）：出典（`sources`）→ 要確認（調査メモ）（`toVerify`）→ 画像の出典（自動。冒頭の肖像画 `portrait`・ぱぱねこ版の絵 `papaneko`・家紋の絵の権利表記を1行ずつ。データには書かない）。
- **書くこと**
  - `sources`：資料ごとに、この人物について何を伝えるかと、確かめた程度（「原本画像と照合」「原典は未確認で、〇〇の引用による」など決まった言い方）。
  - `toVerify`：本文で「要確認」とした事柄ごとに、何が分かっていないか・何に頼っているか・当たるべき資料。
- **書かないこと**：本文に書いていない資料（使っていない出典は消す）。確かめ終えた事柄（本文を直して項目を消す）。

## 表示（文字の色・下線・囲み）

色・下線・囲みは `css/style.css` と `js/person.js` が欄の種類と書き方から自動で付ける。**データには色・太字・下線・HTML のタグを書かない**。データの側で使い分けるのは、下の表の「データの書き方」だけ。色は `:root` の変数か CLAUDE.md の「文字と色」の色に限り、新しい色を足さない。

| 見え方 | 何に付くか | データの書き方 |
|---|---|---|
| 朱 `--accent`・下線なし（マウスを載せると下線） | 説明文の中のリンク（人物・合戦・城） | `links: [{ text, person_id \| battle_id \| castle_id }]`。`text` は説明文に出てくる語のまま |
| 藍 #1f5f93 で「…」に括る | 史料の原文の引用 | `{{…}}`（「」は書名・用語・現代語訳に使う） |
| 朱の枠の小さな札「諸説あり」 | 生没年などの異説 | `uncertain: true` |
| 薄茶の地に金の「▪」の小さな札 | 出典マーカー | `sourceId`（文字列か配列） |
| 薄茶の地の箱・朱の左罫と札「考察」 | 本文の中の記事へのリンク | 家系・疑問の項目の `article_id`、または記事の `relatedPeople` と `relatedBattles` が年表の合戦と合うとき |
| 同じ箱で灰色、札「考察（執筆中）」・リンクなし | 下書きの記事の予告 | `article_id` の記事が `draft: true` |
| 太字・朱の左罫（4px） | この人物への大きな問い | `lens.question` |
| 薄い朱の左罫（3px） | 欄の末尾の疑問 | `questions` の `place` |
| ゴシック体の灰色の小さな札「［リンク先：…］」 | リンク先がその場所自体のページでないときの説明 | `urlLabel` |
| 金の左罫と淡い黄の地（確認済みなら藍の左罫） | 仮置きの注記・凍結中の断り書き | `sourcesChecked`・`role: "frozen"`（文言はコードが出す） |
| 章の見出しは大きな太字（1.5rem）に小さな副題、下に墨の二重線 | 5つの章 | 書かない（`GROUPS` が出す） |
| 札「論点1：兄との関係」・朱の左罫で字下げ | 大きな問いを確かめる論点 | `questions` の `place: "lens"` と `aspect` |
| 朱の上罫・薄茶の地の箱、札「まとめ」（押すと開く。ふだんは閉じる） | 論点を束ねた答え。見立てがあれば、その下に閉じずに朱の左罫の囲み「ぱぱねこの見立て」で出る | `lens.answer`（と、管理人が書いたときだけ `lens.view`）。総論の記事がない人物だけ |
| 朱の左罫の入口「この人物の連載 →」（連載が無く総論の記事だけなら「この問いを捉え直す →」） | 連載の表紙（総論の記事）への入口 | 記事の `index.json` の `rensai` の `person_id`（無ければ `lens.article_id`） |
| 名乗りを朱の「→」でつなぎ、年を（）で添える | 冒頭の「改名」 | `aliases` を古い順に並べ、改めた年を `year` |
| 家紋名の前に小さな家紋の絵、下に注記 | 冒頭の「家紋」 | `kamon.clan_id`（絵は大名家の `kamonImage`）・`kamon.note` |

- **文の幅**：人物ページの文は、欄の右端（冒頭の概要カードや見出しの罫の右端）まで流して折り返す。年表・各欄の説明（`.t-desc`・`.entry-note`）、人物評価の本文、参考書籍の説明に `max-width` を付けない（同じ部品を使う合戦・城の詳細ページも同じ）。考察記事の本文と「ぱぱねこの見立て」（`.my-view`）だけは読みやすさのため 40em のまま。表示を足すときもこの分け方を守る。
- 下線を付けたいときは、データに書かずリンクにする。強調したいだけなら語尾と語順で書き分け、太字や色に頼らない。
- 考察記事の本文（`data/articles/*.md`）はリンクが朱の点線の下線、論拠の要の蛍光線 `==…==` など別の決まりがある（`docs/schema-article.md`）。人物ページのデータには `==…==` や Markdown を書かない。

## 文の区切り・地図・番号・領地の描画

これも `js/person.js` が自動でする。データの側では、下の「データで守ること」だけを守る。

### 章・欄・段落・文の区切り
- **章と欄**：章（5つの組）と欄の見出し・目次は `GROUPS` が出す。データに見出しは書かない。欄の並びを変えるときは `GROUPS` と `docs/schema-person.md` の「ページの並び」と、このスキルの「ページの章立て」を一緒に直す。
- **文**：説明文（`note`・`description`・`text`・`untilNote` など）は、**句点「。」ごとに1行**で出る（かっこの中の句点では切れない。下の段落で書く2つの欄は例外で、文を続けて組む）。だから1文を短く、1文に1つのことを書く。文末の数文字だけが次の行に残らないよう、表示側で詰める。
- **改行と空き**：どの説明文でも、データの改行（JSON では `\n`）はそこで改行し、空行（`\n\n`）は少し間をあけて次の行を始める（`person.js` の `lineBreaks`・`sentSpans`。要約・問い・注記・年表・まとめ・人物評価・挿絵のキャプション・肖像画の注記のすべて）。書き方は下の「改行と空きの入れ方」。
- **段落**：段落に分けられるのは、人物評価の本文（`reputation[].body`）と、まとめの答え・見立て（`lens.answer`・`lens.view`）だけ。**空行（`\n\n`）で段落を分ける**（1つの `\n` は段落の中の改行になる）。
- **出典マーカー**：`sourceId` のマーカーは、最後の文（段落）の末尾に付く。文の中に出典を書き込まない。

### 改行と空きの入れ方
秀長のページ（2026-11-05 に61か所へ入れた）に倣う。文言は変えずに、改行と空きだけで読みやすくする。
- **改行（`\n`）**：1行が長い文（目安は全角40字を超えるもの）は、読点やかっこの切れ目で改行する。`{{…}}` の引用、リンクの語（`links` の `text`）、年号と（西暦）の組の途中では切らない。短い文は切らない。
- **空き（`\n\n`）**：前と後ろで役割が変わるところに入れる。例：問いと、その確かめ方（大きな問い）／事績と、どう終わったか（要約）／史料の記述と、その読み方・要確認（年表の「記録の空白」：史料に現れないこと → よく語られる話とその出どころ）／存命時の評と、その後の動き（人物評価の段落）。同じ話の続きには入れない。
- **欄ごと**：
  - `lens.question`：問いの2行、空き、確かめ方の数行（秀長：「兄に従い、裏方に徹した…「補佐役」。\nよく語られるこの秀長像は、どこまで当たっているのか。\n\n兄との関係、領主として、政権の中で、の三つの面から…確かめ、\n…」）。
  - `summary`：「誰の何か」「何をしたか」を1文ずつ改行し、「どう終わったか」の前に空き。
  - `reputation[].body`・`lens.answer`・`lens.view`：空行で段落を分け、段落の中も1文ずつ改行する。人物評価の最初の1文は見出しになるので、その文の中では改行しない。
  - 注記（`note`・`description`・`text`）：もともと句点ごとに改行して出るので、足すのは長い文の中の改行と、役割の変わり目の空きだけ。
- **入れない欄**：出典（`sources`）と要確認（`toVerify`）。調べものの記録なので、句点ごとの改行のままにする。
- 改行と空きは `\n` で JSON に書く。全角スペースや空の文で間をあけない。

### 地図を出す欄と、出す条件
地図はどれも Leaflet＋OpenStreetMap で、データに地図を書く欄はない。**地点か範囲の分かる項目が1つでもあれば、欄の上に自動で出る**。

| 欄 | 地図 | 項目が地図に載る条件 |
|---|---|---|
| 年表（`timeline`） | 番号付きピン | `battle_id`（合戦の地点）・`castle_id`（城の地点）、または `lat`/`lng`。城・合戦の地点と出来事の場所がずれるときは `lat`/`lng`（と `place`）を書く |
| 領地の変遷（`territories`） | 国・郡の塗り＋番号付きピン＋年代順の線（全体の地図）と、各項目の下の「その時点の領地」の地図 | `province`・`district`、または `lat`/`lng` |
| ゆかりの地・史跡（`spots`・`graves`） | 番号付きピン | `castle_id`（城の地点）、または `lat`/`lng` |

- 座標は OpenStreetMap（Nominatim）で名前を引いて確かめる。見つからず町の中心などを置いたら `approx: true`。
- 近い地点はピン1本にまとまり、拡大すると分かれる。地図の下の説明文も自動で出る。

### 番号の付け方
- **地図の番号と一覧の番号は同じもの**で、どちらも自動で振る。データに番号（①・1. など）を書かない。
- 年表：年月の順に並べ替えた順番（データの並びは問わない）。番号は地図に載る項目にだけ付く。
- 領地の変遷：**データに書いた順**（並べ替えない）。だから年の順に書く。番号は地図に載る項目にだけ付く。
- ゆかりの地：墓所が先、ゆかりの地が後の表示順。
- 本文の数の書き方は「文章の調子」のとおり（年は「天正13年（1585）」）。年表の見出しは「1585年10月」、領地は「1580〜1585年」と表示側で整える。

### 領地の変遷の描き方
- **1項目 = 同じときに一緒に得た国・郡**。1項目に1つの番号と1つの色が付き、一覧の番号・ピン・塗りが同じ色になる（8色を順に使い、9項目目からは同じ色に戻る）。
- **塗る範囲**：国全体なら `province`（例 `"大和国"`）、国の一部なら `district`（例 `"但馬国朝来郡"`。`assets/geo/districts.geojson` の1920年の郡名）。郡と国全体が混じるときは `district` に国名も並べる（例 `["伊勢国安濃郡", "伊賀国"]`）。国の一部なのに `province` を入れると国全体が塗られるので入れない。
- **手放した領地**：`until` を書くと、全体の地図で淡い点線の囲みになり、一覧は「1580〜1585年」と出る。死ぬまで持っていたなら `until` を書かない。事情は `untilNote`（一覧に「→ 1585年」として出る）。
- **その時点の地図**：各項目の下に、その年に持っていた領地だけを出す（その項目を濃く、同時に持っていた他の項目を淡く）。「持っていた」は、その年までに得て、`until` がその年より後のもの。だから `year` と `until` が正しくないと、この地図が崩れる。
- **ピンと線**：`lat`/`lng`（と `place`）を書くと、居城など代表地点にピンが立ち、ピンを年の順に朱の点線でつなぐ。
- **塗れない・塗らない範囲**は `mapNote` に理由を書く（郡全体か分からない、など）。地図の国界は1868年、郡界は1920年の近似で、戦国期の境界とは細部で違う（この断りは地図の下に自動で出る）。

## 作業の順序（詳細ページ）

1. **材料を集める**：下の「調べ方」のとおり。`reference/` の原典を grep し、足りない原典は取得して `reference/` に保存する。
2. **出典（`sources`）を先に立てる**：使う資料ごとに1項目。`note` には「この資料がこの人について何を伝えるか」と「どこまで確かめたか」を書く（下の「出典」）。
3. **本文の欄を埋める**：下の「欄ごとの書き方」の順に（書く順で、ページ上の並びとは違う。並びは上の「ページの章立て」）。確かめた事柄は書き、確かめきれない事柄は要点と「要確認（ページ末尾の調査メモ）」だけを残す。
4. **要確認（`toVerify`）にまとめる**：本文で「要確認」とした事柄を1つずつ項目に立てる。
5. **リンクを張る**：下の「リンクを張る手順」のとおり。このページの説明文から他のページへ（行き）と、他のページの説明文からこのページへ（帰り）の両方を張る。
6. **ほかのページとそろえる**：その人物が出てくる記事（`data/articles/index.json` の `relatedPeople`、本文の `.md`・`drafts/` の論文版）、合戦・城のページ、主役ページの家系・家臣の注記と、日付・経緯・呼び名が食い違っていないかを見る。食い違ったら、原典で確かめた方に全部をそろえ、確かめきれなければ両方を要確認にする（荒木村重の「単身で脱出」「毛利領へ逃れた」は、記事の裏取りで信長公記と食い違うと分かり、人物ページと合戦ページを直した）。
7. **挿絵を入れる**（主役だけ）：下の「illusts（欄の挿絵）」のとおり、案を出して管理人に選んでもらい、仮の SVG を入れる。
8. **改行と空きを入れる**（主役だけ）：文言が固まったら、上の「改行と空きの入れ方」のとおり、長い文に改行を、役割の変わり目に空きを入れる。
9. **仕上げ**：下の「仕上げのチェック」を通す。

秀長のページを基準に、欄ごとの**上限**を決めておく。上限は目標ではない。史料で言えることがそれより少なければ少ないままでよく、伝承で水増ししない。上限を超えそうなら、要点の薄い項目からまとめるか削る。

ほかの欄は秀長と同じくらいを目安にする（改名7・呼び名の変遷8・官位4・領地5・逸話4・諸説と疑問6・成し遂げたこと3・参考書籍6）。`check_person.py` は上限を超えると注意を出す。

## 調べ方

### 原典を引く
- まず `reference/` を grep する（一覧と来歴は `reference/README.md`）。人名は表記ゆれに注意し、時期ごとの呼び名で引く（秀長なら「小一郎」「美濃守」「大納言」「宰相」）。信玄なら「晴信」「徳栄軒」「信玄」「武田大膳大夫」のように、`aliases` と `nameHistory` に入れる呼び名を先に洗い出してから引く。
- 研究書・論文は CiNii・NDL サーチで書誌（著者・書名・刊行年・頁）を確かめる。論文の書誌メモは `reference/cinii/<年>/<著者-短題>.md` に置く。

### 手元にない原典を保存する
使いたい原典が `reference/` になければ、取得して固定スナップショットとして保存してから使う（都度ネットで読んで済ませない）。手順の詳細は `docs/sources.md` の「運用ルール」と「NDL 次世代デジタルライブラリールート」。

1. **探す**：Wikisource に翻刻があるか（`https://ja.wikisource.org/wiki/<書名>`）。なければ NDL サーチの SRU（`https://ndlsearch.ndl.go.jp/api/sru`、`anywhere="書名" AND mediatype="digital"`）でパブリックドメインの活字本を探し、`lab.ndl.go.jp` の book id を得る。
2. **取る**
   - Wikisource：parse API（`action=parse&prop=text&formatversion=2`）で全文を取り、タグを除く。サブページに分かれていれば全部つなぐ。
   - NDL：`https://lab.ndl.go.jp/dl/api/book/fulltext/{id}` の OCR 全文 ZIP を取り、ページ順につなぐ（`D:\private\shiryo\tools\ndl_fulltext.py`）。多巻物は巻ごとに id が違う。原本画像を見るときは同じフォルダの `fetch_ndl_iiif.py` で git 外の `D:\private\shiryo\<史料名>\` に保存し、1コマ3秒以上あける。
3. **置く**：`reference/wikisource/<sourceId>.txt` か `reference/ndl/<sourceId>.txt`。ファイルの先頭に、既存のファイル（例 `reference/wikisource/azai-sandaiki.txt`）と同じ形で来歴を書く：原典・史料区分・注意・底本・取得元（URL と取得日）・ライセンス・用途・sourceId。NDL の OCR なら「OCR／要校正」と書き、コマ番号の区切り（`── コマ N ──`）を残す。
4. **記録する**：`reference/README.md` の収録表と `docs/sources.md` の取得済みの表に1行足す。史料なら `data/sources.json` にも登録する。
- 著作権の残る翻刻（近年の刊本など）は保存しない。書誌と頁だけを出典に書き、中身は「本は未見」などの確かめた程度で示す。

### Web 検索の使い方
- Web 検索（Wikipedia・自治体・博物館・研究機関のページなど）は入口として使ってよい。
- **検索で見つけた事柄に原典があるときは、原典の中身まで当たって反映する**。「〇〇によれば××とある」と書かれていたら、その〇〇（史料・論文）を探して本文を読み、確かめた内容で書く。原典が手に入らなければ「原典は未確認で、〇〇の引用による」と確かめた程度を書き、要確認に回す。
- 原典の分からない Web の記述は、事実の典拠にしない。Wikipedia から引き写した日付・頁は必ず「Wikipedia 経由」と書く。

### 量が多いときはサブエージェントで進める
調べものや書き込みが多いときは、Agent ツールのサブエージェントに分けて並べて進める。目安は次のとおり。
- 原典ごと・欄ごとの洗い出し（例：信長公記・甲陽軍鑑・妙法寺記を、それぞれ別のエージェントで、呼び名の一覧を渡して grep させ、該当箇所と年月を一覧で返させる）。
- 脇役の概要ページをまとめて作るとき、帰りのリンクを張る箇所を探すとき。
- 依頼文には、このスキル（`.claude/skills/person-page/SKILL.md`）の該当する節、対象の id、引く呼び名、返してほしい形（原典名・巻や条・該当文の抜き書き・年月）を書く。エージェントの結果は、本文に入れる前に自分で原典の該当箇所を開いて確かめる（言い換えや取り違えがありうるため）。
- 同じファイルを2つのエージェントに書き込ませない。

## リンクを張る手順

### 行き（このページ → 他のページ）
- このページの説明文に、ページのある人物・合戦・城の語が出てきたら、その項目の `links` に `{ text, person_id | battle_id | castle_id }` を足す（各語の最初の1か所がリンクになる）。合戦・城は項目の `battle_id`・`castle_id` でもつながる。
- リンクを張りたい相手にページがなければ、脇役として概要ページを作るか（リンクに要るときだけ）、リンクにしない。作らないと判断済みの人（CLAUDE.md）にはリンクしない。

### 帰り（他のページ → このページ）
新しくページを作ったとき（脇役の概要ページも）は、すでにあるページの説明文の中のこの人物の名前にもリンクを張る。
1. 探す：`python .claude/skills/person-page/find_mentions.py <id>` で、`data/people`・`data/battles`・`data/castles`・`data/clans` の説明文のうち、この人物の名前（`name` と `aliases` の値）が出てくるのにリンクのない項目を一覧にする。
2. 張る：見つかった項目の `links` に `{ text, person_id }` を足す。`text` は説明文に出てくる形のまま（「信玄」「晴信」など）。別人の同じ呼び名（「信玄」は1人だが「三郎」などは多い）でないか、文脈で確かめる。家系・主君・家臣の項目で `name` しかないものには `person_id` を足す。
3. 記事：その人物が出てくる記事（`data/articles/*.md`）があれば、記事の `relatedPeople`（`data/articles/index.json`）に id を足す。記事の本文は書き換えない。
4. 張り終えたら `check_person.py` を、張った先の人物にも通す。

## 文章の調子

- 常体（だ・である）で、短く平易に。難しい漢語は開く（「〜に任じられた」「〜を領した」程度まで）。史料の原文は `{{…}}` で引き、必要なら直後に（）で意味を添える（例：`{{サテサテ浅猿（あさまし）}}`）。
- **確かさの度合いを語尾で書き分ける**：史料で確かめた事柄は言い切る。通説・伝承は「〜とされる」「〜と伝わる」。研究者の読みは「〜とみる（柴2024）」のように説の持ち主を示す。自分の推定は「〜とみられる」。
- 確かめられないことは書かないか、「史料からは確かめられない」「〜を記す史料は見つかっていない」と書く。**「わからない」も情報**として残す。
- 年は和暦を先に、西暦を（）で添える：「天正13年（1585）」。月日は和暦の月日のまま書く（`era` も「天正19年1月22日」の形）。
- 人名は、地の文では一般的な呼び名（秀吉・信長）、史料を引くときは史料の表記（`{{木下小一郎}}`）。同じ人を初めて出すところで「木下藤吉郎（秀吉）」のように対応させる。
- 広告・アフィリエイトのリンクは `references` だけ。

## 欄ごとの書き方

### summary（一言紹介）
2〜3文。「誰の何か（続柄・立場）」→「何をした人か（代表的な事績2〜3）」→「どう終わったか」の順。異名があれば「」で添える（秀長：「大和大納言」）。`index.json` の `summary` は1〜2文に縮めてよい。

### portrait（肖像画）
秀長の肖像画（`assets/img/portraits/toyotomi-hidenaga.jpg` と、そのデータ）に倣う。
- **選ぶ**：著作権の切れた平面作品（江戸時代以前の肖像画・浮世絵）だけ。Wikimedia Commons のファイルページで、ライセンスがパブリックドメインであることを確かめる。立体物の写真・近現代の作品は使わない。同時代に近い像があればそれを、なければ後世の像を使い、その旨を `note` に書く。
- **画像**：Commons の元画像を取り、**幅480px の JPEG（RGB）**に縮めて `assets/img/portraits/<id>.jpg` に置く（秀長は 480×564）。肖像の一部を切り出したら `caption` か `note` に「部分」と書く。
- **サムネイル**：顔を中心に正方形で切り出した **160×160 の JPEG** を `assets/img/portraits/thumbs/<id>.jpg` に置き、`index.json` の `thumb` に書く。
- **データ**：`src`・`caption`（作品名。例「豊臣秀長像」。権利表記の行の名前にも使う）・`holder`（所蔵。模写なら模写と原本の所蔵を併記）・`note`・`source`（`{ "name": "Wikimedia Commons", "url": ファイルページ }`）・`license`（「パブリックドメイン」）。
- **`note` に書くこと**：いつ・誰が描いたか（伝承なら「〜とされる」）、**没後どれくらい後のものか**、より古い像が別にあればその所蔵と根拠（秀長：春岳院の像は天明8年〈1788〉の作とされ没後約200年、没後まもない文禄2年〈1593〉賛の像は大光院）。
- 見つからなければ `portrait` も `thumb` も省く（「肖像画は未発見」の絵が出る）。
- **表示**：絵の下には `caption` と `note` だけが出る。`holder`・`source`・`license` は、ページ末尾の「画像の出典」に「豊臣秀長像　所蔵：… ／ 出典：…（パブリックドメイン）」の形で出る（`person.js` の `imageCredits`）。

### papaneko（ぱぱねこ版の絵）
秀長のぱぱねこ版（`assets/img/chara/toyotomi-hidenaga.svg` と、そのデータ）に倣う。**主役（詳細ページ）に付ける**。脇役（概要ページ）には付けない。
- **絵**：その人物を、ぱぱねこの派生キャラで描く（顔の決まり・その人物の印・名札の色は `chara/README.md`）。秀長は、肖像画と並べて見比べられるよう、上畳に座る肖像画の形にし、低い折烏帽子と藍の紐の小豆を付け、右上に賛に見立てた名札（藍の縦書き「豊臣秀長」）を置いた。印が決まっていない人物は、描く前に印の案を出して管理人に決めてもらい、`chara/README.md` に書き足す。
- **作る順**：挿絵と同じ（CLAUDE.md）。Claude が仮の SVG（`viewBox="0 0 400 480"`、地色 #fbfaf6 で塗る）を作って `assets/img/chara/<id>.svg` に置く → 管理人が表示を確かめる → Gemini か手描きに差し替える。仮の絵を入れたら `docs/判断待ち.md` に確認待ちの項を立てる。
- **データ**：`src`・`caption`（「ぱぱねこ版の〇〇（イメージ）」。たとえの絵なので「（イメージ）」を付ける。権利表記の行の名前にも使う）・`note`（その人物の印が何を表すかを1文。秀長：「低い折烏帽子と、藍の紐で首に下げた小豆（「大和大納言」にちなむ大納言小豆）が秀長の印。」）・`credit`（省略すると「イラスト：ぱぱねこの戦国見立て（AIで作成）」。管理人の手描きに替えたら「イラスト：ぱぱねこの戦国見立て」と書く）。
- **表示**：肖像画の右に出る。絵の下には `caption` と `note` だけが出て、`credit` はページ末尾の「画像の出典」に出る（`person.js` の `imageCredits`）。肖像画がない人物でも、「肖像画は未発見」の絵の右に出る。

### illusts（欄の挿絵）
秀長ページの8枚（2026-11-05）に倣う。**主役（詳細ページ）だけに付ける**。脇役・凍結中の人物には付けない。
- **枚数と置き場所**：1ページに **5〜10枚**（管理人の指定）。記事のように小見出しごとに1枚とはせず、欄の中身が絵で伝わる要所に置く。秀長の置き場所：大きな問い（`lens`）・人物評価（`reputation`）・成し遂げたこと（`achievements`）・年表（`timeline`）に2枚・逸話（`episodes`）・家系（`family`）・呼び名の変遷（`nameHistory`）。
- **進め方**：Claude が欄・場面・構図・区分（想像図／イメージ）の案を表にして出す → 管理人が番号で選ぶ → 仮の SVG を作って入れる → 管理人が見て、要らない絵は外し、足りなければ追加の案を頼む。秀長で管理人が外した案：郡山入国の行列（領地の変遷）、大納言塚にお参りするぱぱねこ（ゆかりの地）、家臣と与力が並ぶ家中（家臣団）。
- **場面の選び方**：
  - その人物の記事に、同じ場面の挿絵があれば避ける（記事を開いたときに同じ絵を見せない）。同じ話を描くなら、場面ではなく中身を絵にする（「内々の儀は宗易、公儀の事は宰相」は、記事の「宗麟の手を取る秀長」と別に、言葉の中身を描いた「二つの窓口」にした）。
  - 違いを伝える絵は、左右に分けて、明るさ・広さ・人数で差をはっきり出す（「二つの窓口」：左は暗く狭い茶室でひそかに＝内々、右は明るい広間で大名の前で＝公儀。下に「身内の相談・内輪の話」「政権の表の仕事・大名の取り次ぎ」と添える）。
  - 確かめていない伝承を、事実の場面として描かない（「記録の空白」は、案の「中村の田で働く若い秀長（想像図）」を、霧の中を歩く姿の「イメージ」に変えた。百姓をしていた話は後の時代の伝承のため）。記事で否定した通説（温厚な補佐役など）も描かない。
  - 絵に合わせて本文を足すときは、まず原典で確かめ、言えるところまでにとどめる（長島攻めの「兄の名代として」は、信長公記に名代とは書かれていないので、年表に「名代として羽柴勢を率いたとみられる（名代と書いた史料はない）」と書き足し、キャプションも「とみられる」にした）。
- **絵**：`assets/img/illust/<名前>.svg`（`viewBox="0 0 800 450"`、地色 #fbfaf6）。人物はぱぱねこの派生キャラで、印と名札で見分ける（`chara/README.md`）。若いころなど印の一部がまだ付かない時期は、付く印だけにして名札で補う（「記録の空白」の秀長は首の小豆だけ）。作る順と本番の絵への差し替えは挿絵と同じ（CLAUDE.md）。仮の絵を入れたら `docs/判断待ち.md` に確認待ちの項を立てる。
- **データ**：`{ key, item?, src, caption, credit? }` の配列。`key` は置く欄のデータ名で、その欄の見出しのすぐ下に出る（`lens` は問いの文の下）。年表は `item` にその項目の `title` を書くと、その項目の説明の下に出る（出来事の絵は出来事の位置に置く）。同じ欄に2枚以上あればデータの順に並ぶ。`caption` は「題（想像図）。」か「題（イメージ）。」で始め、続けて絵の中身の根拠を1〜2文で書く（史料名・年を入れる）。`credit` は省略で「イラスト：ぱぱねこの戦国見立て（AIで作成）」、手描きなら「イラスト：ぱぱねこの戦国見立て」。表記は絵の下に出る（ページ末尾の「画像の出典」には出ない）。

### kamon（家紋）
- `{ "name": "織田木瓜", "clan_id": "oda" }` の形で書く。家に複数の紋があれば、代表の1つ。
- **絵**：`clan_id` を付けると、その大名家の家紋の絵（`data/clans/index.json` の `kamonImage`）が家紋名の前に出る。絵は大名家と共用で、人物ごとに画像を置かない（`image` は書かない）。権利表記はページ末尾の「画像の出典」に自動で出る。大名家に絵がない紋（荒木村重の「牡丹」など、どの形か特定できないもの）は名前だけになる。新しい家紋の絵を足すときは大名家の `kamonImage` に足す（Commons の家紋の SVG を 240×240 の背景透明 PNG にし、作者・ライセンス・出典を書く。`docs/schema-clan.md`）。家の紋と違う紋を使った人物には `clan_id` を付けない。
- **確かめた程度**：本人が用いたと史料か研究で確かめられた紋はそのまま書く。家の紋を置いただけで本人の使用を確かめていないとき（秀長の五三桐・謙信の上杉笹）は、`note` に「〇〇家の家紋。〇〇自身が用いたことは同時代の史料で確かめていない。要確認（ページ末尾の調査メモ）」と書き（家紋名の下に出る）、`toVerify` に `section: "家紋"` の項目を立てる。後世の家紋集だけが根拠のときも同じ。

### birthplace（出生地）
- `{ "name": 当時の地名, "prefecture": 今の都道府県, "city": 今の市区町村 }`。`name` は国・郡・村まで分かる範囲で当時の呼び方（秀長：「尾張国愛知郡中村」／愛知県／名古屋市）。
- この欄には根拠を書く場所がないので、根拠と異説は `birth.note` に書く（どの史料が出生地をそう書くか。後世の伝承なら「〜と伝わる」）。確かめられなければ要確認へ。城で生まれたとされるなど場所が特定できても、`lat`/`lng` は書かない（地図には出ない）。
- 分からなければ省く。

### images（人物画像）
- 今の人物ページは `images` を表示しない。秀長も空。肖像画は `portrait`、ゆかりの地の写真は扱わないので、**書かない**。
- 載せたい画像が出てきたら、先に表示を作るかを管理人に確かめる。管理人が自分で撮った写真なら、組み込む前に `.claude/rules/own-photo.md` の確認をする。


### aliases と nameHistory（改名と呼び名の変遷）
- `aliases` は**本人の名乗りの移り変わり**（幼名・通称・実名・法名・法号）。冒頭の「改名」の行に、配列の順のまま「→」でつないで出る（並べ替えないので、**改めた順＝古い順**に置く）。`note` に典拠を短く。
- 改めた年が分かるものは `year`（西暦）を付ける。名乗りの後に（1584）と出る。改めた年が分からず史料での初見の年を入れるときは、`note` に「年は〇〇での初見」と書く。年の分からないもの（幼名・通称など）は `year` を付けない。
- 1つの項目に複数の名乗りをまとめない（謙信の「景虎・政虎・輝虎」は、長尾景虎（1543）・上杉政虎（1561）・上杉輝虎（1562）の3項目に分ける）。
- **他人からの呼び名は入れない**（北条方が謙信を呼んだ「長尾輝虎」など）。それは `nameHistory` か `reputation` に書く。異名・通称（「大和大納言」）は、本人がそう呼ばれるようになった年を付けて置いてよい。
- ひな型：秀長は 小竹 → 小一郎 → 木下長秀／羽柴長秀 → 羽柴美濃守（1583）→ 羽柴秀長（1584）→ 大和大納言（1587）→ 法名（1591）。
- `nameHistory` は**史料がその時期に実際どう呼んでいるか**を時系列で。`value` は史料の表記、`note` にどの史料がどこでそう書くかを原文 `{{…}}` で示す。幼少期など年の決まらないものは `era` だけ。
- 改名の時期は研究に頼ることが多い。説の持ち主（著者・年・頁）を書き、食い違いは要確認へ。後世の書き直しが疑われる表記（秀長：播磨別所記の「秀長」）はそう注記する。

### birth / death（生没年）
- `era` は和暦、`year` は西暦。月日が和暦なら `month`/`day` はグレゴリオ暦に直したもの（秀長の没日：天正19年1月22日＝1591年2月15日）。
- **根拠を `note` に書く**（逆算なら何から逆算したか）。異説があれば `uncertain: true` にし、異説とその出どころも書く。後世の創作（ドラマ・小説の誕生日など）は「同時代の史料では確かめられない」と明記する。

### ranks（官位）
任官の日付と根拠を `note` に。日記に見える呼び名の切り替わりと、公卿補任などの名簿の日付が食い違うことが多いので、両方を書いてどちらを採るか（または要確認）を示す。

### family（家系）
- **その人の生前に成立した関係だけ**を置く。死後の縁組は相手側の注記で伝える（秀長の娘・大善院と毛利秀元の縁組は秀長の死後なので、秀元は家系に入れない）。
- `relation` は続柄を具体的に（正室・側室・娘・甥・養子など）。`note` には続柄の補足（誰の子か、のちにどうなったか）を1〜2文。
- 異説のある関係（異父兄弟か否か）は、注記で両説を短く示し、結論は記事に回す。考察記事へは、家系の欄の末尾の疑問（`questions` に `place: "family"`）からつなぎ、同じ記事への `article_id` を項目には付けない（リンクが重なるため。秀長：竹阿弥・秀吉の項目は注記だけ）。
- ページのない家族（与一郎など）も `name` で載せ、根拠の `sourceId` を付ける。

### lords / retainers / yoriki（主君・家臣団・与力）
- 家臣団 `retainers` には、家臣だったことを史料で示せる人を。出仕の始まりが不明なら「仕え始めた年は不明」と書く。
- **主君から付けられた大名は家臣ではないので `yoriki` に分ける**。付けられた経緯（いつ・なぜ・どの史料）を `note` に。名前の分からない与力がいたことは `yorikiNote` に。
- 姓や名が史料によって違う家臣（秀長：吉川平助、羽田・岸田）は、確かな表記だけを本文に、揺れは要確認へ。

### territories（領地）
- 同じときに一緒に与えられた国・郡は1項目にまとめる（地図で同じ番号・色になる）。
- **国の一部しか領していないのに `province` を入れない**。城代・数郡なら `district`（`assets/geo/districts.geojson` の郡名）。郡全体かどうか分からないなら、そう `mapNote` に書く。
- 手放した年 `until` と事情 `untilNote` を書く。手放した時期を示す史料がなければ、何を根拠にそこで切ったかを書く（秀長の近江：「最後の文書は天正3年、天正5年には但馬に入ったのでここまでとした」）。
- 代官として預かったのか自分の知行なのか、石高はどれほどかが分からないときは、そのまま「確定せず」と書く。

### timeline（年表）
- 出来事は**史料で日付を言える範囲**で。`title` は短い名詞句か「〜する」、`description` に何が起きたかと史料の書きぶり（必要なら原文）。
- 合戦は `battle_id`、城は `castle_id`。地図の地点が城・合戦の地点とずれるときは `place`/`lat`/`lng`（推定なら `approx: true`）。
- **史料に現れない期間は伝承で埋めない**。`toYear` を付けた「記録の空白」の項目を1つ置き、なぜ空白なのか、よく語られる話の出どころが後世のものであることを書く（秀長の1541〜1572年）。
- 参陣したかどうか自体が不確かな出来事（秀長：山崎の戦い）は、載せる場合も「〜とされる」で書き、要確認へ。
- 死後の出来事も、その人の家の行く末に関わるものは最後に置いてよい（秀長：秀保の死と断絶）。

### achievements（成し遂げたこと）
3つ前後。題名は短く、`description` は1文。年表の要約で、新しい事実は書かない。

### episodes（逸話）
- 逸話は**史料の性格とセットで**書く。顕彰の文章（天正記）なら「秀吉側の文章なので、やりとりが整えられている可能性はある」のように添える。
- 典拠が二次・孫引きなら `uncertain: true` と「要確認（ページ末尾の調査メモ）」。

### lens（この人物への問い）
- ページの先頭（「捉え直す」の組）に出す、その人物の像そのものを問い直す**大きな問いを1つ**。今よく語られる人物像を挙げ、「いつ、どこから来て、どこまで当たっているのか」の形にすると立てやすい（秀長：「名補佐役」の像）。`title` はその短い言い方。
- `lens.answer`（まとめ）は史料から言える読みだけで書き、たたき台であることを `docs/判断待ち.md` に載せて管理人の確定を待つ。`lens.view`（見立て）は**管理人が書く**。Claude は書かない。
- **論点の記事がそろったら、総論の記事を書いて `lens.article_id` でつなぐ**（人物 → 総論の記事 → 各論点の記事。kousatsu-article スキルの「総論の記事」）。つないだら、論点（`place: "lens"`・`"lensSide"` の `questions`）・答え（`answer`）・見立て（`view`）は総論の記事へ移してデータから消し、人物ページには問いと入口だけを残す。答えも見立ても管理人の判断なので記事の側に置く（答えを2か所に書くと、直すたびにずれる）。ひな型は秀長（`hidenaga-zou`）。総論の記事を表紙にした**連載**（記事の `index.json` の `rensai`）があると、「捉え直す」の組は事実の組（どんな人だっけ？／誰だっけ？）の後ろへ下がり、入口は「この人物の連載 →」になる。人物ページは事実の脚注で、考察は連載が受け持つ。
- 問いを立てるのは詳細ページだけ。概要ページには書かない。

### questions（諸説・疑問）
- 題名は問いの形（「秀吉とは異父兄弟なのか？」）。`text` は2〜3文で、**何が分かれているか・何を確かめるか**だけ。結論は書かない。
- 考察記事があれば `article_id`（下書きの間は「考察（執筆中）」と出る）。人物ページは論点の目次。
- `place` で置き場所を分ける。`lens` の大きな問いを支える問いは `"lens"`、素性の謎は関わる欄（`"family"`・`"nameHistory"` など）の末尾へ。データを読んで出てきた疑問が、その場で考察記事につながるようにする。

### reputation（人物評価）
- `era` は「存命時」「死去後」の2区分か、時代区分。**出典ごとに項目を分け**、各項目に `title`（小見出し）と1つの `sourceId`。
- 存命時は同時代の日記・書状がどう書いたか（原文を引く）。死去後は江戸の軍記・逸話集、近代の小説・ドラマ、現代の研究と、**描かれ方の移り変わり**として並べる。小説は事実の典拠にはしないが、「どう描かれてきたか」の資料として載せてよい。
- 本文は段落を空行（`\n\n`）で分け、段落の中も1文ずつ `\n` で改行する（最初の1文は見出しになるので、その中では改行しない。上の「改行と空きの入れ方」）。

### references（参考書籍）
新しい研究書・評伝を中心に。`note` に「何が書いてある本か」と、このページで何を確かめるのに使うかを書く。`isbn` と `affiliateUrl` を付ける。

### spots と graves（ゆかりの地・墓所）
- `spots` は城跡・神社仏閣・博物館・名物など。城ページがあれば `castle_id`、なければ公式や自治体のページを `url`（その場所自体のページでなければ `urlLabel`）。
- 城ページのない場所（墓所の `places` も）には `lat`/`lng` を付け、欄の上の地図に出す。座標は OpenStreetMap（Nominatim）で名前を引いて確かめ、見つからなければ住所の町の中心を置いて `approx: true`（秀長：春岳院は新中町の中心）。
- `graves.status` は必ず書く（現存・諸説あり・不明・なし）。墓が複数あるなら、どれが何か（墓所と伝わる・供養塔・逆修塔など）を `note` と各 `description` で区別する。

### sources（出典）
- `type` と `primary` の組み合わせは `docs/sources.md` の表どおり：史料＝一次資料／二次資料、研究書・論文・寄稿＝研究、Wikipedia などのネット記事＝付けない、小説・展覧会目録などは `type` だけ（書籍・その他）。
- `year` は成立年や刊行年。史料で成立がはっきりしないときは文字列で「江戸時代初期成立（池田家文庫本に慶長15年〈1610〉の奥書）」のように書いてよい。
- `note` は2つのことを書く。
  1. **この資料がこの人について伝えること**（どの記事・どの条・何年の文書か。原文の要所を `{{…}}` で）。
  2. **確かめた程度**。次の言い方にそろえる：
     - 「原本画像と照合」… 刊本・写本の画像で本文を見た
     - 「Wikisource（〇〇本を底本とする）の本文で確認」… 翻刻で確かめた
     - 「OCR本文による（原本画像とは未照合）」
     - 「原典は未確認で、〇〇の引用による」… 孫引き
     - 「本は未見」「頁は〇〇経由で、本は未見」… 中身を見ていない
     - 「〇〇による」… 成立年など、資料以外から借りた情報の出どころ
- 研究は**誰がどう読んだかの典拠**。説の持ち主と頁を書く。小説家・ライターの一般向け記事、ドラマ解説は出典にしない。
- 新しい**史料**を足したら `data/sources.json` にも登録する（`level`・`yomi`・`usedIn`）。研究・ネット記事は載せない。

### toVerify（要確認・調査メモ）
- 本文に「要確認（ページ末尾の調査メモ）」と書いた事柄ごとに1項目。`section` はページの欄名（生年・呼び名・官位・家系・親族・家臣団・与力・領地・年表・人物評価・ゆかりの地など）、`title` は何を確かめるか。
- `text` には**何が分かっていないか・何と何が食い違うか・いま何に頼っているか**を書く。ネットで探して見つからなかったときは「（2026-10-27時点）」のように日付を添える。
- `checkWith` には当たるべき資料を、書名・刊行年・頁・所蔵先まで具体的に。
- 確かめ終えたら本文を直し、項目を消す。

### sourcesChecked と tags
- 出典を1つずつ当たり、各 `note` に確かめた程度を書き終えたら `sourcesChecked: true`。仮置きの注記が「出典の確認状況」の案内に替わる。途中なら付けない。
- `tags` は家・立場・地域の3つ前後（秀長：豊臣家・戦国大名・大和）。`updatedAt` はその日の日付。
