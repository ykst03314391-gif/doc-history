# 人物ページの作り方（秀長ページをひな型に）

人物ページ（`data/people/<id>.json`）を作る・書き足すときの手順と書き方。ひな型は豊臣秀長のページ `data/people/toyotomi-hidenaga.json`。迷ったら秀長の該当する欄を開いて、同じ形・同じ調子で書く。フィールドの型は `docs/schema-person.md`、出典の当たり先は `docs/sources.md` にある。ここに書くのは、スキーマに載らない**判断と書きぶり**。

## まず、どちらのページを作るのか決める

人物は主役・脇役・名前だけの3段階で扱う（CLAUDE.md の「進め方」）。詳細ページを書くのは主役だけ。

| | 概要ページ（脇役） | 詳細ページ（主役。秀長型） |
|---|---|---|
| いつ | 主役ページや記事からリンクを張るために、その人のページが必要になったとき | 管理人がその人物について考察を書くと決めたとき（考察記事がある人物） |
| 書く欄 | `id`・`name`・`kana`・`summary`・生没年（`birth`/`death`）・`tags`。分かれば `aliases`・`category`・`portrait` | 下の「欄ごとの書き方」のすべて |
| 書かない欄 | 年表・家系・逸話・出典などの詳細 | （`history` はどちらでも書かない） |

- **ページを作るかどうかを先に決める。** 名前が出てくるだけでは作らない。主役ページや記事から参照する必要があるかで判断する。作らない人はリンクにせず `name` だけで書く。判断済みの人（CLAUDE.md の10人）は作らない。新たに「作らない」と決めたら CLAUDE.md の一覧に足す。
- **主役でない人を詳細に書き広げない。** 概要ページの人物を詳細にするのは、管理人がその人を主役にすると決めてから。すでに詳細まで書いてある主役以外の人物（凍結中の46人。`role: "frozen"`）にも書き足さない。主役にすると決まったら、`index.json` と個別ファイルの `role` を `"main"` にする（`docs/schema-person.md`）。
- 詳細ページを作っても、そこから出てくる人物・合戦・城を「新しく作る候補」として広げない。リンクに要る脇役だけを概要で作る。
- 武将でない人（家族・僧・商人など）は `category: "other"`（個別ファイルと `index.json` の両方）。
- 詳細ページで新しい人物にリンクを張るとき、その人の概要ページを同時に作る（`person_id` が空振りしないように）。

## ページの章立て

人物ページは、冒頭の「概要」のあとに5つの章を並べる（並びと章の見出しは `js/person.js` の `GROUPS`、表示の決まりは `docs/schema-person.md` の「ページの並び」）。**考察が主役でデータは脚注**なので、問いを立てる「捉え直す」を先頭に、出典と調査メモを最後に置く。中身のない欄・章は表示されないので、空の欄を埋めるために書かない。

各章は「読者のどんな問いに答えるか」で中身を決める。章ごとに、答える問い・置く欄・書くこと・書かないことは次のとおり。欄の細かい書きぶりは下の「欄ごとの書き方」。

### 概要（ヘッダー。見出しなし）
- **答える問い**：この人は誰で、ひとことで言うと何をした人か。
- **置く欄**：名前・読み（`name`・`kana`）、生没年（`birth`・`death`）、一言紹介（`summary`）、肖像画（`portrait`）、基本情報（別名 `aliases`・家紋 `kamon`・出生地 `birthplace`・分類 `tags`）。仮置きの注記（凍結中なら「詳しく書き足していません」の断り書き）はここに自動で出る。
- **書くこと**：`summary` は「誰の何か」→「代表的な事績2〜3」→「どう終わったか」の2〜3文。読み終えた人が、下の章のどこを読めばいいか見当がつく程度にとどめる。
- **書かないこと**：評価や結論（「名補佐役だった」など）。評価は「捉え直す」で問いとして扱う。
- **脇役（概要ページ）はこの章だけで終わる**。下の5つの章は主役（詳細ページ）だけが持つ。

### 1. 捉え直す ― 本当にそうか？
- **答える問い**：今よく語られるこの人物像は、本当にそうか。どこから来た像か。
- **置く欄**（この順）：この人物への問い（`lens`）→ 人物評価（`reputation`）→ 諸説・疑問（`questions` のうち `place` が `lens` か無指定のもの）→ 関連する考察・記事（自動）。
- **書くこと**
  - `lens`：人物像を問い直す大きな問いを1つ（秀長：「名補佐役」の像は、いつ、どこから来て、どこまで当たっているのか）。`view`（筆者の見立て）は管理人が書く。
  - `reputation`：同時代の日記・書状がどう書いたか（存命時）と、江戸の軍記から近代の小説・現代の研究までの描かれ方の移り変わり（死去後）。出典ごとに1項目。
  - `questions`：大きな問いを支える小さな問い。何が分かれているか・何を確かめるかだけを書き、結論は記事に回す。記事があれば `article_id`。
  - 関連する考察・記事：手で書かない。記事の `relatedPeople` にこの人物の id を入れると出る。ページの中ですでにリンクした記事（`article_id` を付けた家系・疑問の項目や、記事の `relatedBattles` と合う年表の合戦に出したもの）と、下書きの記事は出ない。
- **書かないこと**：問いへの答え（記事の役目）。記事の要約の貼り付け。
- **この時点で考察記事は作らない**。人物ページで立てるのは問い（`lens`・`questions`）までで、その先の記事（`data/articles/` の本文・`index.json` への登録・`drafts/` の論文版）は書かない。記事を書くかどうか、いつ書くかは管理人が決め、決まったら別の作業として起こす。問いの `article_id` は、記事がすでにあるか、管理人が書くと決めて下書きを登録したときだけ付ける。

### 2. どんな人だっけ？ ― 事績と生涯
- **答える問い**：この人は、いつ、どこで、何をしたのか。
- **置く欄**（この順）：成し遂げたこと（`achievements`）→ 年表（`timeline`）→ 領地の変遷（`territories`）→ 逸話・エピソード（`episodes`）。
- **書くこと**
  - `achievements`：生涯の要点3つ前後。年表を縮めたもので、新しい事実は書かない。
  - `timeline`：史料で日付を言える出来事。史料に出てこない期間は「記録の空白」として1項目置く。合戦・城のページへは `battle_id`・`castle_id`（地図にピンが立つ）。
  - `territories`：いつ、どこを、どれだけ持ち、いつ手放したか。国の一部なら郡で塗る。
  - `episodes`：人柄の分かる話を、伝える史料の性格（顕彰の文章か、後世の逸話集か）とセットで。
- **書かないこと**：伝承で埋めた生い立ち。確かめられない参陣を言い切ること（「〜とされる」と要確認にする）。

### 3. 誰だっけ？ ― 家系・主従・呼び名
- **答える問い**：この人は誰の子・誰の家族で、誰に仕え、誰を従え、何と呼ばれたのか。
- **置く欄**（この順）：家系・親族（`family`）→ 仕えた人（`lords`）→ 家臣団（`retainers`）→ 与力（`yoriki`・`yorikiNote`）→ 官位（`ranks`）→ 呼び名の変遷（`nameHistory`）。素性の謎は、関わる欄の末尾に `questions`（`place: "family"`・`"nameHistory"` など）で置く。
- **書くこと**
  - `family`：生前に成立した関係だけ。続柄は具体的に。ページのない家族も名前で載せる。
  - `lords`・`retainers`・`yoriki`：家臣だったと史料で示せる人を家臣団に、主君から付けられた大名は与力に分ける。
  - `ranks`：任官の日付と、日記と名簿で食い違うときの両方の日付。
  - `nameHistory`：その時期に史料が実際どう呼んでいるかを、原文 `{{…}}` で時系列に。
- **書かないこと**：死後の縁組（相手側の注記で伝える）。異説のある続柄の結論（両説を短く示し、記事へ）。

### 4. もっと知りたい！ ― 読む本・行く現地
- **答える問い**：この人のことをもっと知るには、何を読み、どこへ行けばいいか。
- **置く欄**（この順）：参考書籍（`references`）→ ゆかりの地・史跡（`spots`。墓所 `graves` もこの欄の中に出る）。
- **書くこと**
  - `references`：新しい研究書・評伝を中心に、何が書いてある本か。アフィリエイトのリンクはここだけ。
  - `spots`・`graves`：城跡・寺社・博物館など、行ける場所。地図に出すため、城ページか座標を付ける。墓は現存かどうかと、墓所・供養塔などの区別。
- **書かないこと**：小説や一般向けの記事を、事実の典拠として紹介すること（小説は人物評価の「描かれ方」の資料として扱う）。

### 5. 出典と確認状況
- **答える問い**：このページの記述は何に基づき、どこまで確かめてあるか。
- **置く欄**（この順）：出典（`sources`）→ 要確認（調査メモ）（`toVerify`）。
- **書くこと**
  - `sources`：資料ごとに、この人物について何を伝えるかと、確かめた程度（「原本画像と照合」「原典は未確認で、〇〇の引用による」など決まった言い方）。
  - `toVerify`：本文で「要確認」とした事柄ごとに、何が分かっていないか・何に頼っているか・当たるべき資料。
- **書かないこと**：本文に書いていない資料（使っていない出典は消す）。確かめ終えた事柄（本文を直して項目を消す）。

## 表示（文字の色・下線・囲み）

色・下線・囲みは `css/style.css` と `js/person.js` が欄の種類と書き方から自動で付ける。**データには色・太字・下線・HTML のタグを書かない**。データの側で使い分けるのは、下の表の「データの書き方」だけ。色は `:root` の変数か CLAUDE.md の「文字と色」の色に限り、新しい色を足さない。

| 見え方 | 何に付くか | データの書き方 |
|---|---|---|
| 朱 `--accent`・下線なし（マウスを載せると下線） | 説明文の中のリンク（人物・合戦・城） | `links: [{ text, person_id \| battle_id \| castle_id }]`。`text` は説明文に出てくる語のまま |
| 藍 #1f5f93 で「…」に括る | 史料の原文の引用 | `{{…}}`（「」は書名・用語・現代語訳に使う） |
| 朱の枠の小さな札「諸説あり」 | 生没年などの異説 | `uncertain: true` |
| 薄茶の地に金の「▪」の小さな札 | 出典マーカー | `sourceId`（文字列か配列） |
| 薄茶の地の箱・朱の左罫と札「考察」 | 本文の中の記事へのリンク | 家系・疑問の項目の `article_id`、または記事の `relatedPeople` と `relatedBattles` が年表の合戦と合うとき |
| 同じ箱で灰色、札「考察（執筆中）」・リンクなし | 下書きの記事の予告 | `article_id` の記事が `draft: true` |
| 太字・朱の左罫（4px） | この人物への大きな問い | `lens.question` |
| 生成りのパネルの枠、朱の小見出し「筆者の見立て」 | 筆者の見立て | `lens.view`（管理人が書く） |
| 薄い朱の左罫（3px） | 欄の末尾の疑問 | `questions` の `place` |
| ゴシック体の灰色の小さな札「［リンク先：…］」 | リンク先がその場所自体のページでないときの説明 | `urlLabel` |
| 金の左罫と淡い黄の地（確認済みなら藍の左罫） | 仮置きの注記・凍結中の断り書き | `sourcesChecked`・`role: "frozen"`（文言はコードが出す） |
| 章の見出しは大きな太字（1.5rem）に小さな副題、下に墨の二重線 | 5つの章 | 書かない（`GROUPS` が出す） |

- 下線を付けたいときは、データに書かずリンクにする。強調したいだけなら語尾と語順で書き分け、太字や色に頼らない。
- 考察記事の本文（`data/articles/*.md`）はリンクが朱の点線の下線、論拠の要の蛍光線 `==…==` など別の決まりがある（`docs/schema-article.md`）。人物ページのデータには `==…==` や Markdown を書かない。

## 作業の順序（詳細ページ）

1. **材料を集める**：`reference/` の原典を grep する（人名は表記ゆれに注意。秀長なら「小一郎」「美濃守」「大納言」「宰相」など、時期ごとの呼び名で引く）。研究書・論文は CiNii・NDL サーチで書誌を確かめる。Wikipedia は入口に使ってよいが、そこから引き写したものは必ず「〜経由」と書く。
2. **出典（`sources`）を先に立てる**：使う資料ごとに1項目。`note` には「この資料がこの人について何を伝えるか」と「どこまで確かめたか」を書く（下の「出典」）。
3. **本文の欄を埋める**：下の「欄ごとの書き方」の順に（書く順で、ページ上の並びとは違う。並びは上の「ページの章立て」）。確かめた事柄は書き、確かめきれない事柄は要点と「要確認（ページ末尾の調査メモ）」だけを残す。
4. **要確認（`toVerify`）にまとめる**：本文で「要確認」とした事柄を1つずつ項目に立てる。
5. **リンクを張る**：説明文の中で、ページのある人物・合戦・城の語を `links` でリンクにする。
6. **ほかのページとそろえる**：その人物が出てくる記事（`data/articles/index.json` の `relatedPeople`、本文の `.md`・`drafts/` の論文版）、合戦・城のページ、主役ページの家系・家臣の注記と、日付・経緯・呼び名が食い違っていないかを見る。食い違ったら、原典で確かめた方に全部をそろえ、確かめきれなければ両方を要確認にする（荒木村重の「単身で脱出」「毛利領へ逃れた」は、記事の裏取りで信長公記と食い違うと分かり、人物ページと合戦ページを直した）。
7. **仕上げ**：下の「仕上げのチェック」を通す。

## 文章の調子

- 常体（だ・である）で、短く平易に。難しい漢語は開く（「〜に任じられた」「〜を領した」程度まで）。史料の原文は `{{…}}` で引き、必要なら直後に（）で意味を添える（例：`{{サテサテ浅猿（あさまし）}}`）。
- **確かさの度合いを語尾で書き分ける**：史料で確かめた事柄は言い切る。通説・伝承は「〜とされる」「〜と伝わる」。研究者の読みは「〜とみる（柴2024）」のように説の持ち主を示す。自分の推定は「〜とみられる」。
- 確かめられないことは書かないか、「史料からは確かめられない」「〜を記す史料は見つかっていない」と書く。**「わからない」も情報**として残す。
- 年は和暦を先に、西暦を（）で添える：「天正13年（1585）」。月日は和暦の月日のまま書く（`era` も「天正19年1月22日」の形）。
- 人名は、地の文では一般的な呼び名（秀吉・信長）、史料を引くときは史料の表記（`{{木下小一郎}}`）。同じ人を初めて出すところで「木下藤吉郎（秀吉）」のように対応させる。
- 広告・アフィリエイトのリンクは `references` だけ。

## 欄ごとの書き方

### summary（一言紹介）
2〜3文。「誰の何か（続柄・立場）」→「何をした人か（代表的な事績2〜3）」→「どう終わったか」の順。異名があれば「」で添える（秀長：「大和大納言」）。`index.json` の `summary` は1〜2文に縮めてよい。

### portrait（肖像画）
著作権の切れた平面作品だけ（Wikimedia Commons など）。**いつ・誰が描いたか、没後どれくらい後のものか**を `note` に書く。より古い像が別にあるなら併記する（秀長：春岳院の像は没後約200年、文禄2年賛の像は大光院）。見つからなければ省く（noimage が出る）。サムネイルは `index.json` の `thumb`。

### aliases と nameHistory（別名と呼び名の変遷）
- `aliases` は一覧（幼名・通称・実名・法名）。`note` に典拠を短く。
- `nameHistory` は**史料がその時期に実際どう呼んでいるか**を時系列で。`value` は史料の表記、`note` にどの史料がどこでそう書くかを原文 `{{…}}` で示す。幼少期など年の決まらないものは `era` だけ。
- 改名の時期は研究に頼ることが多い。説の持ち主（著者・年・頁）を書き、食い違いは要確認へ。後世の書き直しが疑われる表記（秀長：播磨別所記の「秀長」）はそう注記する。

### birth / death（生没年）
- `era` は和暦、`year` は西暦。月日が和暦なら `month`/`day` はグレゴリオ暦に直したもの（秀長の没日：天正19年1月22日＝1591年2月15日）。
- **根拠を `note` に書く**（逆算なら何から逆算したか）。異説があれば `uncertain: true` にし、異説とその出どころも書く。後世の創作（ドラマ・小説の誕生日など）は「同時代の史料では確かめられない」と明記する。

### ranks（官位）
任官の日付と根拠を `note` に。日記に見える呼び名の切り替わりと、公卿補任などの名簿の日付が食い違うことが多いので、両方を書いてどちらを採るか（または要確認）を示す。

### family（家系）
- **その人の生前に成立した関係だけ**を置く。死後の縁組は相手側の注記で伝える（秀長の娘・大善院と毛利秀元の縁組は秀長の死後なので、秀元は家系に入れない）。
- `relation` は続柄を具体的に（正室・側室・娘・甥・養子など）。`note` には続柄の補足（誰の子か、のちにどうなったか）を1〜2文。
- 異説のある関係（異父兄弟か否か）は、注記で両説を短く示し、結論は記事に回す。考察記事へは、家系の欄の末尾の疑問（`questions` に `place: "family"`）からつなぎ、同じ記事への `article_id` を項目には付けない（リンクが重なるため。秀長：竹阿弥・秀吉の項目は注記だけ）。
- ページのない家族（与一郎など）も `name` で載せ、根拠の `sourceId` を付ける。

### lords / retainers / yoriki（主君・家臣団・与力）
- 家臣団 `retainers` には、家臣だったことを史料で示せる人を。出仕の始まりが不明なら「仕え始めた年は不明」と書く。
- **主君から付けられた大名は家臣ではないので `yoriki` に分ける**。付けられた経緯（いつ・なぜ・どの史料）を `note` に。名前の分からない与力がいたことは `yorikiNote` に。
- 姓や名が史料によって違う家臣（秀長：吉川平助、羽田・岸田）は、確かな表記だけを本文に、揺れは要確認へ。

### territories（領地）
- 同じときに一緒に与えられた国・郡は1項目にまとめる（地図で同じ番号・色になる）。
- **国の一部しか領していないのに `province` を入れない**。城代・数郡なら `district`（`assets/geo/districts.geojson` の郡名）。郡全体かどうか分からないなら、そう `mapNote` に書く。
- 手放した年 `until` と事情 `untilNote` を書く。手放した時期を示す史料がなければ、何を根拠にそこで切ったかを書く（秀長の近江：「最後の文書は天正3年、天正5年には但馬に入ったのでここまでとした」）。
- 代官として預かったのか自分の知行なのか、石高はどれほどかが分からないときは、そのまま「確定せず」と書く。

### timeline（年表）
- 出来事は**史料で日付を言える範囲**で。`title` は短い名詞句か「〜する」、`description` に何が起きたかと史料の書きぶり（必要なら原文）。
- 合戦は `battle_id`、城は `castle_id`。地図の地点が城・合戦の地点とずれるときは `place`/`lat`/`lng`（推定なら `approx: true`）。
- **史料に現れない期間は伝承で埋めない**。`toYear` を付けた「記録の空白」の項目を1つ置き、なぜ空白なのか、よく語られる話の出どころが後世のものであることを書く（秀長の1541〜1572年）。
- 参陣したかどうか自体が不確かな出来事（秀長：山崎の戦い）は、載せる場合も「〜とされる」で書き、要確認へ。
- 死後の出来事も、その人の家の行く末に関わるものは最後に置いてよい（秀長：秀保の死と断絶）。

### achievements（成し遂げたこと）
3つ前後。題名は短く、`description` は1文。年表の要約で、新しい事実は書かない。

### episodes（逸話）
- 逸話は**史料の性格とセットで**書く。顕彰の文章（天正記）なら「秀吉側の文章なので、やりとりが整えられている可能性はある」のように添える。
- 典拠が二次・孫引きなら `uncertain: true` と「要確認（ページ末尾の調査メモ）」。

### lens（この人物への問い）
- ページの先頭（「捉え直す」の組）に出す、その人物の像そのものを問い直す**大きな問いを1つ**。今よく語られる人物像を挙げ、「いつ、どこから来て、どこまで当たっているのか」の形にすると立てやすい（秀長：「名補佐役」の像）。`title` はその短い言い方。
- `view`（筆者の見立て）は**管理人が書く**。Claude は勝手に書かない（下書きを頼まれたら、`drafts/` の論文版の結論から作る）。
- 問いを立てるのは詳細ページだけ。概要ページには書かない。

### questions（諸説・疑問）
- 題名は問いの形（「秀吉とは異父兄弟なのか？」）。`text` は2〜3文で、**何が分かれているか・何を確かめるか**だけ。結論は書かない。
- 考察記事があれば `article_id`（下書きの間は「考察（執筆中）」と出る）。人物ページは論点の目次。
- `place` で置き場所を分ける。`lens` の大きな問いを支える問いは `"lens"`、素性の謎は関わる欄（`"family"`・`"nameHistory"` など）の末尾へ。データを読んで出てきた疑問が、その場で考察記事につながるようにする。

### reputation（人物評価）
- `era` は「存命時」「死去後」の2区分か、時代区分。**出典ごとに項目を分け**、各項目に `title`（小見出し）と1つの `sourceId`。
- 存命時は同時代の日記・書状がどう書いたか（原文を引く）。死去後は江戸の軍記・逸話集、近代の小説・ドラマ、現代の研究と、**描かれ方の移り変わり**として並べる。小説は事実の典拠にはしないが、「どう描かれてきたか」の資料として載せてよい。
- 本文は段落を `\n` で分ける。

### references（参考書籍）
新しい研究書・評伝を中心に。`note` に「何が書いてある本か」と、このページで何を確かめるのに使うかを書く。`isbn` と `affiliateUrl` を付ける。

### spots と graves（ゆかりの地・墓所）
- `spots` は城跡・神社仏閣・博物館・名物など。城ページがあれば `castle_id`、なければ公式や自治体のページを `url`（その場所自体のページでなければ `urlLabel`）。
- 城ページのない場所（墓所の `places` も）には `lat`/`lng` を付け、欄の上の地図に出す。座標は OpenStreetMap（Nominatim）で名前を引いて確かめ、見つからなければ住所の町の中心を置いて `approx: true`（秀長：春岳院は新中町の中心）。
- `graves.status` は必ず書く（現存・諸説あり・不明・なし）。墓が複数あるなら、どれが何か（墓所と伝わる・供養塔・逆修塔など）を `note` と各 `description` で区別する。

### sources（出典）
- `type` と `primary` の組み合わせは `docs/sources.md` の表どおり：史料＝一次資料／二次資料、研究書・論文・寄稿＝研究、Wikipedia などのネット記事＝付けない、小説・展覧会目録などは `type` だけ（書籍・その他）。
- `year` は成立年や刊行年。史料で成立がはっきりしないときは文字列で「江戸時代初期成立（池田家文庫本に慶長15年〈1610〉の奥書）」のように書いてよい。
- `note` は2つのことを書く。
  1. **この資料がこの人について伝えること**（どの記事・どの条・何年の文書か。原文の要所を `{{…}}` で）。
  2. **確かめた程度**。次の言い方にそろえる：
     - 「原本画像と照合」… 刊本・写本の画像で本文を見た
     - 「Wikisource（〇〇本を底本とする）の本文で確認」… 翻刻で確かめた
     - 「OCR本文による（原本画像とは未照合）」
     - 「原典は未確認で、〇〇の引用による」… 孫引き
     - 「本は未見」「頁は〇〇経由で、本は未見」… 中身を見ていない
     - 「〇〇による」… 成立年など、資料以外から借りた情報の出どころ
- 研究は**誰がどう読んだかの典拠**。説の持ち主と頁を書く。小説家・ライターの一般向け記事、ドラマ解説は出典にしない。
- 新しい**史料**を足したら `data/sources.json` にも登録する（`level`・`yomi`・`usedIn`）。研究・ネット記事は載せない。

### toVerify（要確認・調査メモ）
- 本文に「要確認（ページ末尾の調査メモ）」と書いた事柄ごとに1項目。`section` はページの欄名（生年・呼び名・官位・家系・親族・家臣団・与力・領地・年表・人物評価・ゆかりの地など）、`title` は何を確かめるか。
- `text` には**何が分かっていないか・何と何が食い違うか・いま何に頼っているか**を書く。ネットで探して見つからなかったときは「（2026-10-27時点）」のように日付を添える。
- `checkWith` には当たるべき資料を、書名・刊行年・頁・所蔵先まで具体的に。
- 確かめ終えたら本文を直し、項目を消す。

### sourcesChecked と tags
- 出典を1つずつ当たり、各 `note` に確かめた程度を書き終えたら `sourcesChecked: true`。仮置きの注記が「出典の確認状況」の案内に替わる。途中なら付けない。
- `tags` は家・立場・地域の3つ前後（秀長：豊臣家・戦国大名・大和）。`updatedAt` はその日の日付。

## 仕上げのチェック

まず機械で見られるものを確かめる（リポジトリのルートで。複数の id を並べてよい）：

```bash
python .claude/skills/person-page/check_person.py <id>
```

✗（エラー）は直す。△（注意）は目で見て判断する（使っていない出典は、本当に要らなければ消す。「要確認」の数と `toVerify` の数は一致しなくてよいが、対応は確かめる）。スクリプトが見るのは、下の印 ⚙ の項目。

- [ ] ⚙ `index.json` に登録・更新した（`name`・`kana`・`role`・`summary`・`birthYear`/`birthEra`・`deathYear`/`deathEra`・`tags`・`thumb`・`category`）。個別ファイルと値がそろっている
- [ ] 手を入れたら `index.json` の `update`（`date` と、何を直したかの箇条2つまで）を書き換えた。「最近更新した人物」に出る。履歴は持たず、最後の1回だけ残す
- [ ] ⚙ JSON として読める
- [ ] ⚙ すべての `sourceId` が `sources[].id` にある。使っていない出典がない
- [ ] ⚙ `person_id` / `battle_id` / `castle_id` / `article_id` のリンク先が存在する（なければ概要ページを作るか、リンクを外す）
- [ ] ⚙ `links` の `text` が、その項目の説明文に実際に出てくる
- [ ] 原文の引用は「」でなく `{{…}}`。書名・用語・現代語訳は「」（⚙ は `{{` と `}}` の対応だけ見る）
- [ ] 本文の「要確認」と `toVerify` の項目が対応している（⚙ は要確認があるのに `toVerify` がない場合だけ見る）
- [ ] 家系に死後の関係を入れていない／⚙ `history` を書いていない
- [ ] 記事・合戦・城・ほかの人物ページの記述と食い違っていない（作業の順序の6）
- [ ] スキーマにないフィールドを足したら `docs/schema-person.md` も更新した
- [ ] 新しい史料を `data/sources.json` に登録した
- [ ] ブラウザで表示を確かめた（`python -m http.server 8765` → `person.html?id=<id>`。地図・年表のピン・出典マーカー・リンク）
