# 公開と更新の方針

サイトを公開したあと、考察記事をどう出していくかの方針。2026-11-02 に管理人と決めた。

## 基本：ストックして小出しにする

書いた考察記事は、大部分をストックとして持っておき、**週2〜3本ずつ小出しにする**。

- 本数よりも、**決まった間隔で途切れずに出ていること**を大事にする。一度にまとめて出して、そのあと間が空くより、少ない本数でも続いているほうが「生きているサイト」に見える。
- 書く側も、締め切りに追われずに出典を確かめる時間が取れる。

## 公開の日に出す分

最初に記事が少ないとサイトが薄く見えるので、**公開の日に5〜6本**を出し、残りを小出しにする。種類が混ざるように選ぶ（どんなサイトかが伝わるように）。

- 秀長の記事を数本（ひな型の人物で、DBのページともいちばんつながっている）
- 信長の記事
- 経済の総論
- 旅の記事を1本

## ストックの減り方

記事のストックは思ったより早くなくなる（たとえば14本あって、公開の日に6本出すと、残り8本は週2〜3本で3〜4週間でなくなる）。そのあとは書く速さがそのまま公開の速さになるので、次のようにする。

- 出す本数は、**続けられる書く速さに合わせる**。週3本と週1本を行ったり来たりするより、週1〜2本をずっと続けるほうがよい。
- 目安として、**ストックが4週間分を切ったら、出す本数を減らす**。

## 出すときに気をつけること

- **リンク切れ**：まだ出していない記事へのリンクは、公開用の書き出し（`tools/build-site.py`）が文字だけにし、一覧・人物ページからも外す。それでも、リンクの張り先が先に公開されるような順番で出すほうが、読者には親切。
- **連作は順番どおりに**：秀長の連作のように続きものの記事は、順番を崩さない。
- **日付は公開した日**：一覧・トップに出る日付は、書き出しのときに `publish`（公開日）に置き換わる。
- **記事でない更新**：記事のない週も、トピック（新説・お出かけ）の追加や、主役のページで出典を確かめ終えたことを「更新」として出せる。

## 読者の声の受け方

2026-11-02 に管理人と決めた。**公開の時点では、公開のコメント欄は置かない。** 記事末に「誤り・出典のご指摘」の窓口を置き、感想は SNS での共有で受ける。

- **ご指摘の窓口**：記事末に「誤り・出典のご指摘はこちら」を置き、外部のフォーム（Google フォームなど）で受ける。届いた内容は公開せず、管理人だけが読む。出典の食い違いの指摘は記事や DB の仮置きを直す手がかりになるので、これは公開の日から置く。
- **公開のコメント欄を置かない理由**
  - 戦国ものは説の対立や「推し武将」で荒れやすく、スパムも来る。一人で毎日見て消すのは負担が大きい。
  - 公開してしばらくは読者が少なく、どの記事も「コメント0件」になる。上の「生きているサイト」に見せる方針と逆になる。
  - 一人の考察が主役のサイトなので、記事の下で他人の説の言い合いが目立つと性格がぶれる。
  - 静的サイトで使える外部のサービスに合うものがない。giscus・utterances は書き込みに GitHub のアカウントが要り、読者の多くは持っていない。Disqus は広告と追跡が入り、記事本文に広告を挟まない方針に反する。
- **あとで考えること**：読者が増えて反応を見たくなったら、管理人の承認を経て表示する形の公開コメント欄を考える。

## 仕組み（2026-11-12 に作った）

静的サイトなので予約投稿の仕組みはない。そこで、公開用の書き出し（`tools/build-site.py`）で出す記事を絞る。

- 記事ごとに `data/articles/index.json` の `publish` に公開日を書く。書き出しは、その日を迎えた記事だけを出す。**`publish` を書いていない記事は出さない**（書き忘れでうっかり出ないように）。
- 出さない記事は、本文の `.md` も配信しないので、URL を直接打っても読めない。
- **公開の日に、書き出してプッシュ（公開先へ上げる）する**（プッシュは管理人の指示があったときだけという今の運用にそのまま合う）。`--as-of <日付>` で、その日の見え方を前もって確かめられる。
- 記事末の「ご指摘の窓口」（上の「読者の声の受け方」）は、まだ作っていない（`docs/公開までの残課題.md`）。
