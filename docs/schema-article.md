# 記事（article）スキーマ設計 v0.1

考察・新説・コラム・旅記事など、**管理人の視点や意見を打ち出す読み物**を扱う。
これは Wikipedia との最大の差別化点（「主観・考察」）を担うコンテンツタイプ。

## 構成方針

記事は「メタデータ」と「本文」を分けて管理する。

- **本文**：`data/articles/<id>.md`（Markdown 1 記事 1 ファイル）
  - 執筆・編集のしやすさを優先し Markdown で書く
  - 表示時に `marked`（CDN）で HTML へ変換
- **メタデータ**：`data/articles/index.json` の配列に集約
  - 一覧表示・詳細ページの見出し・関連人物リンクに使う
  - 本文とは別に持つことで、一覧生成やパースが軽くなる

## 記事の階層（特集 series）

記事は「特集に属する記事」と「単発の一般記事」に分かれる。

- **特集（series）**：大きなテーマでまとめた連載。例：
  - `economics`「経済で見る戦国時代」
  - `myth-busting`「社会の通説っておかしくね？」（信長の革新性・荒木村重・本能寺・秀吉の出自 など）
- **一般記事**：どの特集にも属さない単発記事（例：手取川の考察）

`data/articles/index.json` は `series`（特集の定義一覧）と `articles`（記事一覧）を持つ。
記事は `series` フィールドに特集の `id` を書くと、その特集に属する。未設定なら一般記事。

特集の中はさらに `group` でサブ分類できる。例：「経済で見る戦国時代」を
`総論`（全体を俯瞰）と `大名家別の事例`（織田家・武田家などの個別事例）に分ける。
`group` 未設定の記事は特集の直下（グループ見出しなし）に表示される。

> 将来、大名家（clan）エンティティを作ったら、「大名家別の事例」は `relatedClan` で
> 大名家ページからも辿れるようにする。当面は `group` の文字列で運用する。

### Series（特集の定義）
```
{ "id": string,          // 記事の series から参照
  "title": string,
  "description"?: string,
  "order"?: number }      // 一覧での並び順（小さいほど先。任意）
```

## メタデータ（index.json の各要素）

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | string | 一意なID（例：`tedorigawa-kenshin`）。`<id>.md` と対応 |
| `title` | string | 記事タイトル |
| `series` | string | 属する特集の `id`（未設定なら一般記事） |
| `group` | string | 特集内のサブグループ名（例：`総論` / `大名家別の事例`）。任意 |
| `category` | string | 分類：`考察` / `新説` / `コラム` / `旅・史跡` / `ゲーム考察` など |
| `summary` | string | 一覧・SEO 用の要約 |
| `date` | string | 公開日（YYYY-MM-DD） |
| `updatedAt` | string | 更新日（YYYY-MM-DD、任意） |
| `author` | string | 執筆者（任意）。省略するか「管理人」なら、日付の横にぱぱねこの顔と「ぱぱねこ」を出す（管理人＝ぱぱねこ）。ほかの人が書いたときだけ名前を書く |
| `image` | Image | 冒頭画像 `{ "src", "caption"?, "credit"?, "sourceUrl"?, "license"?, "licenseUrl"? }`（任意）。一覧カードのサムネイルにもなる。`credit` は「撮影：〇〇、Wikimedia Commons」のように撮影者と出典を書き、`sourceUrl`（出典のページ）・`licenseUrl`（CC ライセンスの条文）があればリンクにする。城・合戦・人物の写真を使うときは、その `photo`／`portrait` の表記を写す。詳細ページで**タイトル直下**に表示。**権利注意**：パブリックドメイン画像（Wikimedia Commons の肖像画等）を `credit`/`license` 明記で、または自作画像を使う。自分で撮った写真は `credit` を「撮影：ぱぱねこの戦国見立て（2026年11月）」、`license` を "CC BY 4.0"（`licenseUrl` は https://creativecommons.org/licenses/by/4.0/deed.ja ）とし、載せる前に `.claude/rules/own-photo.md` の確認をする。参考イメージは caption に明記 |
| `references` | Reference[] | 関連書籍（アフィリエイト）`{ "title", "author"?, "affiliateUrl"?, "note"? }`（任意）。記事**末尾**に「関連書籍」として表示。開示文つき・`rel="sponsored"`。可読性のため本文には挟まない |
| `relatedPeople` | string[] | 関連する人物の `person_id`（DB連携。詳細ページで相互リンク） |
| `relatedBattles` | string[] | 関連する合戦の `battle_id`（任意、将来用） |
| `tags` | string[] | タグ（任意） |
| `draft` | boolean | 下書き（true の記事は一覧に出さない、任意） |

## 本文（Markdown）の書き方の指針

> **前提：記事は2層でつくる。** まず `drafts/<id>.md` に**論文版オリジナル**（厳密・出典完備・論証つき）を書き、この Web 記事（`data/articles/<id>.md`）はそれを**噛み砕いた公開版**にする。詳細は [`../drafts/README.md`](../drafts/README.md)・README「記事は2層でつくる」。

差別化の観点から、記事には以下を意識して書く。

- **切り口・主張を明確に**：通説の紹介にとどめず、「私はこう考える」を書く
- **出典を示す**：主張の根拠となる史料・書籍を本文末の「参考文献」に列挙する
- **諸説を尊重**：断定を避けるべき箇所は「〜とも言われる」「近年は〜という見方もある」と明記
- **DBへ誘導**：登場人物は人物ページへリンクする
  例：`[上杉謙信](person.html?id=uesugi-kenshin)`

### 強調と囲みの記法

飛ばし読みでも筋が追えるように、強調でメリハリをつける。付けすぎると効かなくなるので、小見出し1つにつき太字1か所・マーカー1か所までを目安にする。`この**「…」…**` のように、文字のすぐあとに `**「` と続けると太字にならない（Markdown の決まり）。太字の始まりを `**この「…」` と前の語に寄せる。

| 記法 | 表示 | 使いどころ |
|---|---|---|
| `**…**` | 太字 | **筆者の主張・その節の答え**（「秀長の立場は、兄の信頼の上に立っていた」） |
| `==…==` | 金の蛍光線（`<mark>`） | **論拠の要になる事実**（「信長が秀長を直臣にしようとした記録はなく」）。リンクの点線と紛れないよう、下線ではなく蛍光線にしている |
| `{{…}}` | 藍の「…」 | 原文の引用。強調は重ねない |
| `<div class="lead-answer"><span class="lead-answer-label">先に答えを言うと</span><p>…</p></div>` | 朱の上罫の囲み（札の頭にぱぱねこの顔） | 問いのすぐ下に置く、記事の答え（2〜3文）。史料からどこまで言えるか（管理人の読み）だけを書き、一人称の意見は見立てへ回す |
| `<p class="sec-conclusion"><span class="sec-conclusion-label">論点①の結論</span>…</p>` | 朱の左罫の囲み（札の頭にぱぱねこの顔） | 論点ごとの結論。史料から言えること（管理人の読み）。一人称の意見は書かない |
| `<div class="my-view">`・空行・段落・空行・`</div>` | 朱の左罫の囲み（論点の結論と同じ枠・地。文字は本文の太さ）、札「ぱぱねこの見立て」と顔は自動 | 筆者（管理人＝ぱぱねこ）の意見の段落。「私は〜と考える」「私には思える」のように、史料から言えることを越えた見立ては**必ず**これで包む（囲む・囲まないの目安は kousatsu-article スキルの「書きぶり」）。中は Markdown のまま書ける。答え・結論の言い直しは書かず、史料の外へ出る考え（問いの立て直し・たとえでの言い換え・仮定への賭けなど）を書く |
| `\| 年月日 \| できごと \| 出典 \|` の表 | 罫線の表（見出しの行は薄茶の地、3列目は小さく灰色） | 年表。出来事の流れは箇条書きにせず、必ず「年月日・できごと・出典」の3列の表にする。原典で確かめられなかった出典は「出典未確認」 |

### 本文の画像

本文に画像を入れるときは、段落のあいだに次の1行を置く（前後は空行）。写真・肖像と権利表記（撮影者・所蔵・ライセンス・出典）は DB から引くので、記事には書かない。

| 記法 | 引く先 |
|---|---|
| `![[castle:<castle_id>]]` | `data/castles/index.json` の `photo` |
| `![[battle:<battle_id>]]` | `data/battles/index.json` の `photo` |
| `![[person:<person_id>]]` | `data/people/<person_id>.json` の `portrait`（縦長なので小さめに出す） |
| `![[illust:<名前>\|説明]]` | 挿絵 `assets/img/illust/<名前>.svg`（DBは引かず、表記は「イラスト：ぱぱねこの戦国見立て（AIで作成）」と出す。場面の絵なら説明に「（想像図）」、たとえの絵なら「（イメージ）」と書く） |
| `![[zu:<名前>\|題\|説明]]` | 図解 `assets/img/zu/<名前>.svg`（関係図など。罫線の箱に入れ、藍の「図」の札と題を付けて挿絵と見分ける。説明は図の下に出し、表記は「作図：ぱぱねこの戦国見立て（AIで作成）」。SVG の地色は塗らない） |
| `![[manga:<名前>\|題\|説明]]` | 記事末の漫画 `assets/img/manga/<名前>.svg`（1・2・4コマのどれか。2本を空行1つで続けて書くと横に並ぶ〔ぱぱねこが当時の人物に聞く形と当時の人物だけの形。キャラは `chara/README.md`〕。朱の「漫画」の札と題を付け、説明は絵の下に出す。説明に「（創作）」と書く。表記は「イラスト：ぱぱねこの戦国見立て（AIで作成）」） |

- `![[castle:arioka|有岡城跡。村重はここを出て尼崎へ移った]]` のように `|` のあとに書くと、説明を差し替える（そのときは DB の `note` は出さない。「模擬天守」などの断りが要る写真は、差し替えた説明にも書く）。
- DB に写真・肖像のない ID は何も出さない。DB にない画像を使いたいときは、先にその城・合戦・人物の `photo`／`portrait` に権利表記つきで登録する。
- 挿絵は、文章が続いて読みにくいところの息継ぎに、論点ごとに1枚くらいを目安に入れる。史料で確かめられない姿（顔・服装・家紋など）は描き込まない。
- 目安は、節の中身と結びつく画像だけを1本につき数枚まで。冒頭画像（`image`）と同じ画像は本文に重ねない。

## 表示仕様

- 記事一覧：`articles.html` … `index.json` からカード表示（`draft` は除外）
- 記事詳細：`article.html?id=<id>` … メタを `index.json` から引き、本文 `<id>.md` を取得して表示
  - 冒頭にタイトル・カテゴリ・日付
  - 末尾に「関連人物」（`relatedPeople` を人物ページへリンク）
